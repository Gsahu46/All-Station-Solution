The problem in real life

  1. The web app gets loan rules

    "At most 3 books, nothing while a fine is unpaid" is written straight into the web controller.

  2. A kiosk arrives

    Its developer copies the rules into the kiosk's controller. A year later someone "simplifies" the copy: the kiosk now lends a 4th book and ignores fines. Nobody notices for months.

  3. The fix

    Move every rule into one service. Both the web app and the kiosk call it, so there is one copy of each rule, and changing a rule changes it everywhere.

A rule written twice will, one day, say two different things.

What are we building?

A lending API with two ways in, the web (POST /loans) and a self-service kiosk (POST /kiosk/checkouts), plus returns and a member's loans. Every rule is in one service behind both.

An everyday analogy

A library with a front desk and a self-service machine. Both ask the same librarian's rule book; the machine does not keep its own photocopy that nobody updates.

How it works in 4 steps

  1. Controller: reads the request (ids from the web, card and barcode from the kiosk).
  2. Service: finds the member and book, applies every rule, decides.
  3. Repository: saves the loan, or the return and its fine.
  4. Back out: a refusal becomes the same 409 with a reason, whichever way in was used.
Check yourself: the library changes the limit from 3 books to 5. How many files change?

One line in LoanService (and its test). Neither controller knows the limit exists.

What this station is not

  • No database. Repositories are interfaces with in-memory implementations; a database version would replace them without changing the service.
  • No sign-in. Members are named by id or card.
  • No payments. Fines are recorded; challenge 1 records paying them.

Business problem

City Library (a fictional public library) lends books through its website and a self-service kiosk. The rules were written into the website's controller and copied into the kiosk's. The copies drifted, so the kiosk enforced different rules from the desk, and members found out first.

Acceptance criteria

  1. Given a member with fewer than 3 books and no fine, then a loan for 14 days (201), from the web or the kiosk.
  2. Given a member with 3 books out, then 409 LIMIT_REACHED, from either way in.
  3. Given a member with an unpaid fine, then 409 UNPAID_FINE, from either way in.
  4. Given a book already on loan, then 409 BOOK_ON_LOAN.
  5. Given a return 5 days late, then a fine of ₹25, added to the member; returning twice is 409 ALREADY_RETURNED.
  6. Given an unknown member, book, card or loan, then 404; a missing field, 400.

Requirements

  • Demo rules: 3 books at a time, 14 days per loan, ₹5 per late day, no loans with a fine unpaid.
  • Controllers hold no rules; the service holds all of them; repositories only store and find.
  • Dependencies arrive through constructors; "today" comes from an injected clock, in India time.
  • Kiosk card numbers and barcodes are trimmed and upper-cased with Locale.ROOT.

Learning objectives

  • Split an API into controller, service and repository, and say what belongs in each.
  • Use constructor injection and repository interfaces.
  • Unit-test a service with Mockito mocks.
  • Choose between a unit test, a @WebMvcTest slice and a full @SpringBootTest.

The trap

Plausible but wrong

Business rules in controllers, copied into a second entry point and drifting.

The first test runs the two inline copies side by side: the web says no, the kiosk says yes, for a 4th book and for a member with a fine. The second sends the same members through the real web API and the real kiosk: the same 409 and the same reason from both. While building, letting the kiosk save loans without the service turned 1 test red, an off-by-one in the limit turned 2 red, and dropping the fine rule turned 2 red.

One @RestControllerAdvice turns the service's refusals and not-founds into problems for both controllers.

package com.citylibrary.loans;

import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

/** One translation of the service's answers into HTTP, shared by both controllers. */
@RestControllerAdvice
class LoanErrors {

    @ExceptionHandler(LoanService.Refused.class)
    ProblemDetail refused(LoanService.Refused e) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, e.getMessage());
        p.setTitle("Loan refused");
        p.setProperty("reason", e.reason);
        return p;
    }

    @ExceptionHandler(LoanService.NotFound.class)
    ProblemDetail notFound(LoanService.NotFound e) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
        p.setTitle("Not found");
        return p;
    }
}

Does

Why

package com.citylibrary.loans;

import org.springframework.stereotype.Service;

import java.time.Clock;
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;
import java.util.List;
import java.util.UUID;

/**
 * Every loan rule, in one place. The web API and the kiosk both call this; neither has a rule of its own.
 * Rules (demo rules for this library): at most 3 books out per member; no new loan while a fine is unpaid; a book is
 * lent to one member at a time; 14 days per loan; Rs 5 a day for each late day.
 */
@Service
class LoanService {

    static final int MAX_BOOKS = 3;
    static final int LOAN_DAYS = 14;
    static final long FINE_PER_DAY_PAISE = 500;

    enum Reason { LIMIT_REACHED, UNPAID_FINE, BOOK_ON_LOAN, ALREADY_RETURNED }

    /** A rule said no. Carries why, so every entry point can explain it the same way. */
    static final class Refused extends RuntimeException {
        final Reason reason;

        Refused(Reason reason, String message) {
            super(message);
            this.reason = reason;
        }
    }

    static final class NotFound extends RuntimeException {
        NotFound(String message) {
            super(message);
        }
    }

    private final Repositories.MemberRepository members;
    private final Repositories.BookRepository books;
    private final Repositories.LoanRepository loans;
    private final Clock clock;

    /** Constructor injection: every dependency is visible, final, and easy to replace in a unit test. */
    LoanService(Repositories.MemberRepository members, Repositories.BookRepository books, Repositories.LoanRepository loans, Clock clock) {
        this.members = members;
        this.books = books;
        this.loans = loans;
        this.clock = clock;
    }

    /** synchronized: check-then-save across repositories must not interleave. Safe while one instance runs. */
    synchronized Model.Loan borrow(String memberId, String bookId) {
        Model.Member member = members.findById(memberId).orElseThrow(() -> new NotFound("No member " + memberId + "."));
        Model.Book book = books.findById(bookId).orElseThrow(() -> new NotFound("No book " + bookId + "."));
        if (member.unpaidFinePaise() > 0) {
            throw new Refused(Reason.UNPAID_FINE, member.name() + " has an unpaid fine of Rs " + rupees(member.unpaidFinePaise()) + ".");
        }
        long out = loans.findByMember(memberId).stream().filter(Model.Loan::active).count();
        if (out >= MAX_BOOKS) {
            throw new Refused(Reason.LIMIT_REACHED, member.name() + " already has " + out + " books out; the limit is " + MAX_BOOKS + ".");
        }
        if (loans.findActiveByBook(bookId).isPresent()) {
            throw new Refused(Reason.BOOK_ON_LOAN, "\"" + book.title() + "\" is already on loan.");
        }
        LocalDate today = LocalDate.now(clock);
        Model.Loan loan = new Model.Loan("l-" + UUID.randomUUID().toString().substring(0, 8), memberId, bookId, today,
                today.plusDays(LOAN_DAYS), null, 0);
        loans.save(loan);
        return loan;
    }

    /** The kiosk knows a library card and a barcode, not ids. Same rules, through the same method. */
    Model.Loan borrowAtKiosk(String cardNumber, String barcode) {
        Model.Member member = members.findByCardNumber(cardNumber).orElseThrow(() -> new NotFound("No member with card " + cardNumber + "."));
        Model.Book book = books.findByBarcode(barcode).orElseThrow(() -> new NotFound("No book with barcode " + barcode + "."));
        return borrow(member.id(), book.id());
    }

    synchronized Model.Loan giveBack(String loanId) {
        Model.Loan loan = loans.findById(loanId).orElseThrow(() -> new NotFound("No loan " + loanId + "."));
        if (!loan.active()) {
            throw new Refused(Reason.ALREADY_RETURNED, "Loan " + loanId + " was returned on " + loan.returnedOn() + ".");
        }
        LocalDate today = LocalDate.now(clock);
        long lateDays = Math.max(0, ChronoUnit.DAYS.between(loan.dueOn(), today));
        long fine = lateDays * FINE_PER_DAY_PAISE;
        Model.Loan returned = new Model.Loan(loan.id(), loan.memberId(), loan.bookId(), loan.borrowedOn(), loan.dueOn(), today, fine);
        loans.save(returned);
        if (fine > 0) {
            members.findById(loan.memberId()).ifPresent(m -> members.save(m.withFine(fine)));
        }
        return returned;
    }

    List<Model.Loan> loansOf(String memberId) {
        members.findById(memberId).orElseThrow(() -> new NotFound("No member " + memberId + "."));
        return loans.findByMember(memberId);
    }

    private static String rupees(long paise) {
        return paise / 100 + "." + String.format("%02d", paise % 100);
    }
}

package com.citylibrary.loans;

import java.util.List;
import java.util.Optional;

/**
 * What the service needs from storage, as interfaces. The service never knows whether a map or a database sits
 * behind them; tests replace them with mocks.
 */
final class Repositories {

    private Repositories() {
    }

    interface MemberRepository {
        Optional<Model.Member> findById(String id);

        Optional<Model.Member> findByCardNumber(String cardNumber);

        void save(Model.Member member);
    }

    interface BookRepository {
        Optional<Model.Book> findById(String id);

        Optional<Model.Book> findByBarcode(String barcode);
    }

    interface LoanRepository {
        Optional<Model.Loan> findById(String id);

        List<Model.Loan> findByMember(String memberId);

        Optional<Model.Loan> findActiveByBook(String bookId);

        void save(Model.Loan loan);
    }

package com.citylibrary.loans;

import org.springframework.stereotype.Service;

import java.time.Clock;
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;
import java.util.List;
import java.util.UUID;

/**
 * Every loan rule, in one place. The web API and the kiosk both call this; neither has a rule of its own.
 * Rules (demo rules for this library): at most 3 books out per member; no new loan while a fine is unpaid; a book is
 * lent to one member at a time; 14 days per loan; Rs 5 a day for each late day.
 */
@Service
class LoanService {

    static final int MAX_BOOKS = 3;
    static final int LOAN_DAYS = 14;
    static final long FINE_PER_DAY_PAISE = 500;

    static final int MAX_RENEWALS = 2;

    enum Reason { LIMIT_REACHED, UNPAID_FINE, BOOK_ON_LOAN, ALREADY_RETURNED, RENEWAL_LIMIT, OVERDUE, OVERPAYMENT }

    /** A rule said no. Carries why, so every entry point can explain it the same way. */
    static final class Refused extends RuntimeException {
        final Reason reason;

        Refused(Reason reason, String message) {
            super(message);
            this.reason = reason;
        }
    }

    static final class NotFound extends RuntimeException {
        NotFound(String message) {
            super(message);
        }
    }

    private final Repositories.MemberRepository members;
    private final Repositories.BookRepository books;
    private final Repositories.LoanRepository loans;
    private final Clock clock;

    /** Constructor injection: every dependency is visible, final, and easy to replace in a unit test. */
    LoanService(Repositories.MemberRepository members, Repositories.BookRepository books, Repositories.LoanRepository loans, Clock clock) {
        this.members = members;
        this.books = books;
        this.loans = loans;
        this.clock = clock;
    }

    /** synchronized: check-then-save across repositories must not interleave. Safe while one instance runs. */
    synchronized Model.Loan borrow(String memberId, String bookId) {

Interview takeaways

What goes in a controller, a service and a repository?

Controller: HTTP in and out, input shape. Service: business rules and decisions. Repository: storing and finding records. Rules never go in the controller.

Why constructor injection?

Dependencies are explicit and final, the object is complete after construction, and a test can build it with mocks in one line, without Spring.

Why repository interfaces?

The service depends on what it needs, not on how it is stored: an in-memory, JDBC or JPA implementation can be swapped without touching the rules.

Unit test, @WebMvcTest or @SpringBootTest?

Unit tests for rules (fast, precise); @WebMvcTest for HTTP mapping with the service mocked; @SpringBootTest to prove the whole app works together. Most tests should be the first kind.

What does a Mockito mock let you check?

What the code under test asked for and saved: verify(loans, never()).save(any()) proves a refused loan is never stored.
