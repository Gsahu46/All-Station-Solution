The problem in real life

  1. Rohan books a 6:30 yoga class

    The FitNest app calls /bookClass. The answer is 200, with {"success": false}.

  2. The app shows "Something went wrong"

    Was the class full? Had he already booked it? Did the class exist? The answer was the same in all three cases, so the app could only guess.

  3. The fix

    Name things, not actions: POST /classes/1/bookings. Answer each outcome with its own status: 201 booked, 409 full or already yours, 404 no such class.

A status code is the first thing a client reads. When every answer is 200, every client has to dig through the body and guess.

What are we building?

A small class-booking API designed around resources: list classes by date, book a class, cancel a booking, list a member's bookings. Every outcome has the status code that means it.

An everyday analogy

A library does not have a counter called "doBorrowBook". It has books (things), and you borrow, return or renew them (actions). When something fails, the librarian says why: "someone has it" is different from "we don't have that book". URLs are the things; HTTP methods are the actions; status codes are the librarian's reasons.

How it works in 4 steps

  1. See the timetable: GET /classes?date=2026-10-19. The date filters the collection, so it is a query parameter.
  2. Book: POST /classes/1/bookings with your member id. A booking belongs to a class, so it is created under the class.
  3. The answer says what happened: 201 with the new booking's address, or 409 (full, already booked), or 404 (no such class).
  4. Cancel: DELETE /bookings/{id}. The booking has its own address now; the answer is 204.
Check yourself: the class is full. Why 409 and not 404 or 400?

404 would mean the class does not exist, but it does. 400 would mean the request is malformed, but it is fine; the same request would have worked an hour ago. 409 says the request conflicts with the current state: the class is full right now.

What this station is not

  • No login. The member id is sent in the body, so anyone could book for anyone. Real APIs take the member from the signed-in user (security stations).
  • No database. Bookings live in memory.
  • No waitlist and no cancellation deadline. The deadline is a design task in Practice.

Business problem

FitNest (a fictional chain of gyms) has a class-booking API with URLs like /bookClass, /cancelBooking and /getMemberBookings, and it answers 200 to everything, with {"success": false, "message": …} on failure. The app team cannot show members why a booking failed, monitoring cannot count errors (every request "succeeded"), and each new feature adds another verb URL.

Acceptance criteria

  1. Given a date, when the app asks for classes, then 200 with that day's classes in start-time order, each with spots left.
  2. Given a class with space, when a member books, then 201 with Location: /bookings/{id}, and that URL returns the booking.
  3. Given a full class, then 409 Class is full. Given the member already booked it, then 409 Already booked, naming the existing booking.
  4. Given an unknown class, then 404. Given an unknown or missing member id, then 400.
  5. Given a booking, when it is cancelled, then 204 with no body, the spot is free again, and the booking's URL returns 404.
  6. Given a member, then GET /members/{id}/bookings lists their bookings; an unknown member is 404.

Requirements

  • URLs are nouns. Methods are the verbs. No /bookClass, no /cancelBooking.
  • Path parameters identify a resource; query parameters filter a collection.
  • Status codes by meaning: 200 read, 201 created, 204 done with no body, 400 bad request, 404 no such resource, 409 conflicts with current state.
  • Dates are ISO (2026-10-19); times are the gym's local time.
  • Errors are RFC 9457 problems.

Learning objectives

  • Name resources with nouns and choose between nested and top-level URLs.
  • Choose a path or a query parameter.
  • Pick 200, 201, 204, 400, 404 or 409 by what happened.
  • Return Location on create and 204 on delete.
  • Keep "what happened" (the outcome) separate from "which status code" (the HTTP answer).

The trap

Plausible but wrong

Verbs in URLs and 200 for every outcome, so clients cannot tell what happened.

It feels natural to name endpoints after actions, and {"success": false} looks informative. The first test shows the cost: a full class, a double booking and a class that does not exist all come back as the same 200 with the same message. The second test sends the same three requests to the resource API and gets 409, 409 (with a different title) and 404. Removing the capacity check was tried while building: 3 tests went red.

package com.fitnest.classes;

import jakarta.validation.Valid;
import org.springframework.format.annotation.DateTimeFormat;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.http.ResponseEntity;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.net.URI;
import java.time.LocalDate;
import java.util.List;
import java.util.UUID;

/**
 * URLs name things (nouns); the HTTP method says what to do with them. Each outcome has its own status code:
 * 200 here it is, 201 created, 204 done with nothing to return, 404 no such thing, 409 conflicts with the current state.
 */
@RestController
class ClassController {

    private final ClassSchedule schedule;

    ClassController(ClassSchedule schedule) {
        this.schedule = schedule;
    }

    /** A filter on a collection is a query parameter: /classes?date=2026-10-19. */
    @GetMapping("/classes")
    List<GymClass> classes(@RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate date) {
        return schedule.on(date);
    }

    /** A booking is created under the class it is for: the class is in the path, the member in the body. */
    @PostMapping("/classes/{classId}/bookings")
    ResponseEntity<Booking> book(@PathVariable long classId, @Valid @RequestBody BookingRequest request) {
        if (!schedule.memberExists(request.memberId())) {
            throw problem(HttpStatus.BAD_REQUEST, "Unknown member", "No member has the id " + request.memberId() + ".");
        }
        return switch (schedule.book(classId, request.memberId())) {
            case BookingOutcome.Booked(Booking b) -> ResponseEntity.created(URI.create("/bookings/" + b.id())).body(b);
            case BookingOutcome.ClassNotFound() -> throw problem(HttpStatus.NOT_FOUND, "Class not found", "No class has the id " + classId + ".");
            case BookingOutcome.ClassFull() -> throw problem(HttpStatus.CONFLICT, "Class is full", "Every spot in this class is taken.");
            case BookingOutcome.AlreadyBooked(UUID existing) -> throw problem(HttpStatus.CONFLICT, "Already booked",
                    "This member already has booking " + existing + " for this class.");
        };
    }

    /** Once created, a booking is addressed on its own: /bookings/{id}. Nobody needs the class id to find it. */
    @GetMapping("/bookings/{id}")
    Booking booking(@PathVariable UUID id) {
        return schedule.booking(id).orElseThrow(() -> bookingNotFound(id));
    }

    @DeleteMapping("/bookings/{id}")
    ResponseEntity<Void> cancel(@PathVariable UUID id) {
        if (!schedule.cancel(id)) {
            throw bookingNotFound(id);
        }
        return ResponseEntity.noContent().build(); // 204: cancelled, nothing to send back
    }

    @GetMapping("/members/{memberId}/bookings")
    List<Booking> memberBookings(@PathVariable long memberId) {
        if (!schedule.memberExists(memberId)) {
            throw problem(HttpStatus.NOT_FOUND, "Member not found", "No member has the id " + memberId + ".");
        }
        return schedule.forMember(memberId);
    }

    private static ErrorResponseException bookingNotFound(UUID id) {
        return problem(HttpStatus.NOT_FOUND, "Booking not found", "No booking has the id " + id + ".");
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail body = ProblemDetail.forStatusAndDetail(status, detail);
        body.setTitle(title);
        return new ErrorResponseException(status, body, null);
    }
}

    }

    }

    }

    }

src/main/java/com/fitnest/classes/ClassSchedule.java

Does
Holds classes, members and bookings; books, cancels and lists.
Why
One place owns the rules: capacity and one booking per member per class.
Without it
Rules scattered across endpoints.
  • synchronized: "count, then add" cannot interleave with another request, so a class of 2 never gets 3.
  • clearBookings exists for tests only, so each test starts empty.
package com.fitnest.classes;

import org.springframework.stereotype.Component;

import java.time.Instant;
import java.time.LocalDate;
import java.time.LocalTime;
import java.time.temporal.ChronoUnit;
import java.util.Comparator;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.Set;
import java.util.UUID;

/**
 * Classes, members and bookings, in memory. Every method that reads or changes bookings is synchronized:
 * "count the bookings, then add one" must not interleave with another request, or a class of 2 could get 3.
 * (One lock is fine for one gym in memory; a database does this with constraints and transactions in later stations.)
 */
@Component
class ClassSchedule {

    private static final LocalDate MON = LocalDate.of(2026, 10, 19);
    private final Map<Long, GymClass> classes = Map.of(
            1L, new GymClass(1, "Morning Yoga", "Kavya", MON, LocalTime.of(6, 30), 2, 0),
            2L, new GymClass(2, "HIIT Blast", "Arjun", MON, LocalTime.of(7, 30), 20, 0),
            3L, new GymClass(3, "Zumba", "Kavya", MON, LocalTime.of(18, 0), 15, 0),
            4L, new GymClass(4, "Pilates", "Meher", MON.plusDays(1), LocalTime.of(7, 0), 10, 0));
    private final Set<Long> members = Set.of(101L, 102L, 103L);
    private final Map<UUID, Booking> bookings = new LinkedHashMap<>();

    synchronized List<GymClass> on(LocalDate date) {
        return classes.values().stream()
                .filter(c -> c.date().equals(date))
                .sorted(Comparator.comparing(GymClass::startTime))
                .map(c -> c.withSpotsLeft(c.capacity() - booked(c.id())))
                .toList();
    }

    boolean memberExists(long memberId) {
        return members.contains(memberId);
    }

    synchronized BookingOutcome book(long classId, long memberId) {
        GymClass c = classes.get(classId);
        if (c == null) {
            return new BookingOutcome.ClassNotFound();
        }
        Optional<Booking> existing = bookings.values().stream()
                .filter(b -> b.classId() == classId && b.memberId() == memberId).findFirst();
        if (existing.isPresent()) {
            return new BookingOutcome.AlreadyBooked(existing.get().id());
        }
        if (booked(classId) >= c.capacity()) {
            return new BookingOutcome.ClassFull();
        }
        Booking b = new Booking(UUID.randomUUID(), classId, memberId, Instant.now().truncatedTo(ChronoUnit.MILLIS));
        bookings.put(b.id(), b);
        return new BookingOutcome.Booked(b);
    }

    synchronized Optional<Booking> booking(UUID id) {
        return Optional.ofNullable(bookings.get(id));
    }

    /** True if a booking was removed; false if there was none with this id. */
    synchronized boolean cancel(UUID id) {
        return bookings.remove(id) != null;
    }

    synchronized List<Booking> forMember(long memberId) {

/**
 * Spring already turns an invalid @Valid body into an RFC 9457 problem (the base class). We add an "errors" map,

@RestControllerAdvice

    protected ResponseEntity<Object> handleMethodArgumentNotValid(
            MethodArgumentNotValidException ex, HttpHeaders headers, HttpStatusCode status, WebRequest request) {

        ex.getBindingResult().getFieldErrors().forEach(e -> errors.putIfAbsent(e.getField(), e.getDefaultMessage()));

package com.fitnest.classes;

import org.springframework.stereotype.Component;

import java.time.Instant;
import java.time.LocalDate;
import java.time.LocalTime;
import java.time.temporal.ChronoUnit;
import java.util.Comparator;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.Set;
import java.util.UUID;

/**
 * Classes, members and bookings, in memory. Every method that reads or changes bookings is synchronized:
 * "count the bookings, then add one" must not interleave with another request, or a class of 2 could get 3.
 * (One lock is fine for one gym in memory; a database does this with constraints and transactions in later stations.)
 */
@Component
class ClassSchedule {

    private static final LocalDate MON = LocalDate.of(2026, 10, 19);
    /** Challenge 2: capacity can change, so the map must accept updates (all access is synchronized). */
    private final Map<Long, GymClass> classes = new HashMap<>(Map.of(
            1L, new GymClass(1, "Morning Yoga", "Kavya", MON, LocalTime.of(6, 30), 2, 0),
            2L, new GymClass(2, "HIIT Blast", "Arjun", MON, LocalTime.of(7, 30), 20, 0),
            3L, new GymClass(3, "Zumba", "Kavya", MON, LocalTime.of(18, 0), 15, 0),
            4L, new GymClass(4, "Pilates", "Meher", MON.plusDays(1), LocalTime.of(7, 0), 10, 0)));
    private final Set<Long> members = Set.of(101L, 102L, 103L);
    private final Map<UUID, Booking> bookings = new LinkedHashMap<>();

    synchronized List<GymClass> on(LocalDate date) {
        return classes.values().stream()
                .filter(c -> c.date().equals(date))
                .sorted(Comparator.comparing(GymClass::startTime))
                .map(c -> c.withSpotsLeft(c.capacity() - booked(c.id())))
                .toList();
    }

    boolean memberExists(long memberId) {
        return members.contains(memberId);
    }

    synchronized BookingOutcome book(long classId, long memberId) {
        GymClass c = classes.get(classId);
        if (c == null) {
            return new BookingOutcome.ClassNotFound();
        }
        Optional<Booking> existing = bookings.values().stream()
                .filter(b -> b.classId() == classId && b.memberId() == memberId).findFirst();
        if (existing.isPresent()) {
            return new BookingOutcome.AlreadyBooked(existing.get().id());
        }
        if (booked(classId) >= c.capacity()) {
            return new BookingOutcome.ClassFull();
        }
        Booking b = new Booking(UUID.randomUUID(), classId, memberId, Instant.now().truncatedTo(ChronoUnit.MILLIS));
        bookings.put(b.id(), b);
        return new BookingOutcome.Booked(b);
    }

    synchronized Optional<Booking> booking(UUID id) {
        return Optional.ofNullable(bookings.get(id));
    }

    /** True if a booking was removed; false if there was none with this id. */
    synchronized boolean cancel(UUID id) {
        return bookings.remove(id) != null;
    }

    synchronized List<Booking> forMember(long memberId) {
        return bookings.values().stream().filter(b -> b.memberId() == memberId).toList();
    }

    /** Challenge 1: one class's bookings, in the order they were made (the map keeps insertion order). */
    synchronized Optional<List<Booking>> roster(long classId) {
        if (!classes.containsKey(classId)) {
            return Optional.empty();
        }
        return Optional.of(bookings.values().stream().filter(b -> b.classId() == classId).toList());
    }

    /** Challenge 2. The outcome, not a status code: the controller decides what each one means in HTTP. */
    enum CapacityChange { UPDATED, CLASS_NOT_FOUND, BELOW_BOOKINGS }

    synchronized CapacityChange setCapacity(long classId, int capacity) {
        GymClass c = classes.get(classId);
        if (c == null) {
            return CapacityChange.CLASS_NOT_FOUND;
        }
        if (capacity < booked(classId)) {
            return CapacityChange.BELOW_BOOKINGS;
        }
        classes.put(classId, new GymClass(c.id(), c.name(), c.trainer(), c.date(), c.startTime(), capacity, 0));
        return CapacityChange.UPDATED;
    }

    synchronized Optional<GymClass> find(long classId) {
        return Optional.ofNullable(classes.get(classId)).map(c -> c.withSpotsLeft(c.capacity() - booked(c.id())));
    }

    /** For tests only: start each test from an empty booking list. */
    synchronized void clearBookings() {
        bookings.clear();
    }

    private int booked(long classId) {
        return (int) bookings.values().stream().filter(b -> b.classId() == classId).count();
    }
}

package com.fitnest.classes;

import jakarta.validation.Valid;
import org.springframework.format.annotation.DateTimeFormat;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.http.ResponseEntity;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PatchMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.net.URI;
import java.time.LocalDate;
import java.util.List;
import java.util.UUID;

/**
 * URLs name things (nouns); the HTTP method says what to do with them. Each outcome has its own status code:
 * 200 here it is, 201 created, 204 done with nothing to return, 404 no such thing, 409 conflicts with the current state.
 */
@RestController
class ClassController {

    private final ClassSchedule schedule;

    ClassController(ClassSchedule schedule) {
        this.schedule = schedule;
    }

    /** A filter on a collection is a query parameter: /classes?date=2026-10-19. */
    @GetMapping("/classes")
    List<GymClass> classes(@RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate date) {
        return schedule.on(date);
    }

    /** A booking is created under the class it is for: the class is in the path, the member in the body. */
    @PostMapping("/classes/{classId}/bookings")
    ResponseEntity<Booking> book(@PathVariable long classId, @Valid @RequestBody BookingRequest request) {
        if (!schedule.memberExists(request.memberId())) {
            throw problem(HttpStatus.BAD_REQUEST, "Unknown member", "No member has the id " + request.memberId() + ".");
        }
        return switch (schedule.book(classId, request.memberId())) {
            case BookingOutcome.Booked(Booking b) -> ResponseEntity.created(URI.create("/bookings/" + b.id())).body(b);
            case BookingOutcome.ClassNotFound() -> throw classNotFound(classId);
            case BookingOutcome.ClassFull() -> throw problem(HttpStatus.CONFLICT, "Class is full", "Every spot in this class is taken.");
            case BookingOutcome.AlreadyBooked(UUID existing) -> throw problem(HttpStatus.CONFLICT, "Already booked",
                    "This member already has booking " + existing + " for this class.");
        };
    }

    /** Challenge 1: the roster is the class's own collection of bookings, so it is nested under the class. */
    @GetMapping("/classes/{classId}/bookings")
    List<Booking> roster(@PathVariable long classId) {
        return schedule.roster(classId).orElseThrow(() -> classNotFound(classId));
    }

    /** Challenge 2: PATCH changes part of the class. 409 when the change conflicts with the bookings already made. */
    @PatchMapping("/classes/{classId}")
    GymClass setCapacity(@PathVariable long classId, @Valid @RequestBody CapacityRequest request) {
        return switch (schedule.setCapacity(classId, request.capacity())) {
            case UPDATED -> schedule.find(classId).orElseThrow();
            case CLASS_NOT_FOUND -> throw classNotFound(classId);
            case BELOW_BOOKINGS -> throw problem(HttpStatus.CONFLICT, "Capacity below bookings",
                    "More members have booked this class than the new capacity allows.");
        };
    }

    /** Once created, a booking is addressed on its own: /bookings/{id}. Nobody needs the class id to find it. */
    @GetMapping("/bookings/{id}")
    Booking booking(@PathVariable UUID id) {
        return schedule.booking(id).orElseThrow(() -> bookingNotFound(id));
    }

    @DeleteMapping("/bookings/{id}")
    ResponseEntity<Void> cancel(@PathVariable UUID id) {
        if (!schedule.cancel(id)) {
            throw bookingNotFound(id);
        }
        return ResponseEntity.noContent().build(); // 204: cancelled, nothing to send back
    }

    @GetMapping("/members/{memberId}/bookings")
    List<Booking> memberBookings(@PathVariable long memberId) {
        if (!schedule.memberExists(memberId)) {
            throw problem(HttpStatus.NOT_FOUND, "Member not found", "No member has the id " + memberId + ".");
        }
        return schedule.forMember(memberId);
    }

    private static ErrorResponseException classNotFound(long classId) {
        return problem(HttpStatus.NOT_FOUND, "Class not found", "No class has the id " + classId + ".");
    }

    private static ErrorResponseException bookingNotFound(UUID id) {
        return problem(HttpStatus.NOT_FOUND, "Booking not found", "No booking has the id " + id + ".");
    }

package com.fitnest.classes;

import org.springframework.stereotype.Component;

import java.time.Instant;
import java.time.LocalDate;
import java.time.LocalTime;
import java.time.temporal.ChronoUnit;
import java.util.Comparator;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.Set;
import java.util.UUID;

/**
 * Classes, members and bookings, in memory. Every method that reads or changes bookings is synchronized:
 * "count the bookings, then add one" must not interleave with another request, or a class of 2 could get 3.
 * (One lock is fine for one gym in memory; a database does this with constraints and transactions in later stations.)
 */
@Component
class ClassSchedule {

    private static final LocalDate MON = LocalDate.of(2026, 10, 19);
    /** Challenge 2: capacity can change, so the map must accept updates (all access is synchronized). */
    private final Map<Long, GymClass> classes = new HashMap<>(Map.of(
            1L, new GymClass(1, "Morning Yoga", "Kavya", MON, LocalTime.of(6, 30), 2, 0),
            2L, new GymClass(2, "HIIT Blast", "Arjun", MON, LocalTime.of(7, 30), 20, 0),
            3L, new GymClass(3, "Zumba", "Kavya", MON, LocalTime.of(18, 0), 15, 0),
            4L, new GymClass(4, "Pilates", "Meher", MON.plusDays(1), LocalTime.of(7, 0), 10, 0)));
    private final Set<Long> members = Set.of(101L, 102L, 103L);
    private final Map<UUID, Booking> bookings = new LinkedHashMap<>();

    synchronized List<GymClass> on(LocalDate date) {
        return classes.values().stream()
                .filter(c -> c.date().equals(date))
                .sorted(Comparator.comparing(GymClass::startTime))
                .map(c -> c.withSpotsLeft(c.capacity() - booked(c.id())))
                .toList();
    }

    boolean memberExists(long memberId) {
        return members.contains(memberId);
    }

    synchronized BookingOutcome book(long classId, long memberId) {
        GymClass c = classes.get(classId);
        if (c == null) {
            return new BookingOutcome.ClassNotFound();
        }
        Optional<Booking> existing = bookings.values().stream()
                .filter(b -> b.classId() == classId && b.memberId() == memberId).findFirst();
        if (existing.isPresent()) {
            return new BookingOutcome.AlreadyBooked(existing.get().id());
        }
        if (booked(classId) >= c.capacity()) {
            return new BookingOutcome.ClassFull();
        }
        Booking b = new Booking(UUID.randomUUID(), classId, memberId, Instant.now().truncatedTo(ChronoUnit.MILLIS));
        bookings.put(b.id(), b);
        return new BookingOutcome.Booked(b);
    }

    synchronized Optional<Booking> booking(UUID id) {
        return Optional.ofNullable(bookings.get(id));
    }

    /** True if a booking was removed; false if there was none with this id. */
    synchronized boolean cancel(UUID id) {
        return bookings.remove(id) != null;
    }

    synchronized List<Booking> forMember(long memberId) {
        return bookings.values().stream().filter(b -> b.memberId() == memberId).toList();
    }

    /** Challenge 1: one class's bookings, in the order they were made (the map keeps insertion order). */
    synchronized Optional<List<Booking>> roster(long classId) {
        if (!classes.containsKey(classId)) {
            return Optional.empty();
        }
        return Optional.of(bookings.values().stream().filter(b -> b.classId() == classId).toList());
    }

    /** Challenge 2. The outcome, not a status code: the controller decides what each one means in HTTP. */
    enum CapacityChange { UPDATED, CLASS_NOT_FOUND, BELOW_BOOKINGS }

    synchronized CapacityChange setCapacity(long classId, int capacity) {
        GymClass c = classes.get(classId);
        if (c == null) {
            return CapacityChange.CLASS_NOT_FOUND;
        }
        if (capacity < booked(classId)) {
            return CapacityChange.BELOW_BOOKINGS;
        }
        classes.put(classId, new GymClass(c.id(), c.name(), c.trainer(), c.date(), c.startTime(), capacity, 0));
        return CapacityChange.UPDATED;
    }

    synchronized Optional<GymClass> find(long classId) {
        return Optional.ofNullable(classes.get(classId)).map(c -> c.withSpotsLeft(c.capacity() - booked(c.id())));
    }

    /** For tests only: start each test from an empty booking list. */
    synchronized void clearBookings() {
        bookings.clear();
    }

    private int booked(long classId) {
        return (int) bookings.values().stream().filter(b -> b.classId() == classId).count();
    }
}

challenge/solution/ClassController.java

package com.fitnest.classes;

import jakarta.validation.Valid;
import org.springframework.format.annotation.DateTimeFormat;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.http.ResponseEntity;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PatchMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.net.URI;
import java.time.LocalDate;
import java.util.List;
import java.util.UUID;

/**
 * URLs name things (nouns); the HTTP method says what to do with them. Each outcome has its own status code:
 * 200 here it is, 201 created, 204 done with nothing to return, 404 no such thing, 409 conflicts with the current state.
 */
@RestController
class ClassController {

    private final ClassSchedule schedule;

    ClassController(ClassSchedule schedule) {
        this.schedule = schedule;
    }

    /** A filter on a collection is a query parameter: /classes?date=2026-10-19. */
    @GetMapping("/classes")
    List<GymClass> classes(@RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate date) {
        return schedule.on(date);
    }

    /** A booking is created under the class it is for: the class is in the path, the member in the body. */
    @PostMapping("/classes/{classId}/bookings")
    ResponseEntity<Booking> book(@PathVariable long classId, @Valid @RequestBody BookingRequest request) {
        if (!schedule.memberExists(request.memberId())) {
            throw problem(HttpStatus.BAD_REQUEST, "Unknown member", "No member has the id " + request.memberId() + ".");
        }
        return switch (schedule.book(classId, request.memberId())) {
            case BookingOutcome.Booked(Booking b) -> ResponseEntity.created(URI.create("/bookings/" + b.id())).body(b);
            case BookingOutcome.ClassNotFound() -> throw classNotFound(classId);
            case BookingOutcome.ClassFull() -> throw problem(HttpStatus.CONFLICT, "Class is full", "Every spot in this class is taken.");
            case BookingOutcome.AlreadyBooked(UUID existing) -> throw problem(HttpStatus.CONFLICT, "Already booked",
                    "This member already has booking " + existing + " for this class.");
        };
    }

    /** Challenge 1: the roster is the class's own collection of bookings, so it is nested under the class. */
    @GetMapping("/classes/{classId}/bookings")
    List<Booking> roster(@PathVariable long classId) {
        return schedule.roster(classId).orElseThrow(() -> classNotFound(classId));
    }

    /** Challenge 2: PATCH changes part of the class. 409 when the change conflicts with the bookings already made. */
    @PatchMapping("/classes/{classId}")
    GymClass setCapacity(@PathVariable long classId, @Valid @RequestBody CapacityRequest request) {
        return switch (schedule.setCapacity(classId, request.capacity())) {
            case UPDATED -> schedule.find(classId).orElseThrow();
            case CLASS_NOT_FOUND -> throw classNotFound(classId);
            case BELOW_BOOKINGS -> throw problem(HttpStatus.CONFLICT, "Capacity below bookings",
                    "More members have booked this class than the new capacity allows.");
        };
    }

    /** Once created, a booking is addressed on its own: /bookings/{id}. Nobody needs the class id to find it. */
    @GetMapping("/bookings/{id}")
    Booking booking(@PathVariable UUID id) {
        return schedule.booking(id).orElseThrow(() -> bookingNotFound(id));
    }

    @DeleteMapping("/bookings/{id}")
    ResponseEntity<Void> cancel(@PathVariable UUID id) {
        if (!schedule.cancel(id)) {
            throw bookingNotFound(id);
        }
        return ResponseEntity.noContent().build(); // 204: cancelled, nothing to send back
    }

    @GetMapping("/members/{memberId}/bookings")
    List<Booking> memberBookings(@PathVariable long memberId) {
        if (!schedule.memberExists(memberId)) {
            throw problem(HttpStatus.NOT_FOUND, "Member not found", "No member has the id " + memberId + ".");
        }
        return schedule.forMember(memberId);
    }

    private static ErrorResponseException classNotFound(long classId) {
        return problem(HttpStatus.NOT_FOUND, "Class not found", "No class has the id " + classId + ".");
    }

    private static ErrorResponseException bookingNotFound(UUID id) {
        return problem(HttpStatus.NOT_FOUND, "Booking not found", "No booking has the id " + id + ".");
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail body = ProblemDetail.forStatusAndDetail(status, detail);
        body.setTitle(title);
        return new ErrorResponseException(status, body, null);
    }
}

Interview takeaways

Why are verbs in URLs a problem?

The HTTP method already is the verb. Verb URLs multiply (one per action), hide which resource is affected, and lose the built-in meaning of methods: caches, proxies and clients know GET is safe and DELETE removes, but nothing knows what /cancelBooking does.

Nested or top-level: /classes/{id}/bookings or /bookings?

Nest when the child only makes sense inside its parent and you create or list it there. Give it a top-level address once it has its own id, so callers do not need the parent's id to read or cancel it. This station does both.

Path parameter or query parameter?

A path parameter identifies a resource (/bookings/{id}). A query parameter filters, sorts or pages a collection (/classes?date=...).

409 or 400 for a full class?

400 means the request itself is wrong. A full class is a conflict with the current state: the same request would succeed with a free spot. That is 409.

What should DELETE return?

204 No Content when it succeeds and there is nothing useful to send. Here, a repeat DELETE is 404 because the booking is gone; station 008 discusses when 204 for both is the better contract.
