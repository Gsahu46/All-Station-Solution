The problem in real life

  1. Asha pays ₹1,000 for dinner for three

    The app splits it as ₹333.33 each. Three people owe ₹999.99. One paisa is gone, and Asha is the one who lost it.

  2. After a week in Goa

    Settling up shows 12 payments: everyone pays everyone back for every bill.

  3. The fix

    Split in whole paise and hand the leftover paise to someone by a fixed rule, so the parts always add up. Then net everyone's balance and pair the biggest debtor with the biggest creditor: at most one payment fewer than people.

Rounding each part on its own loses money. Decide who gets the remainder.

What are we building?

POST /groups/{id}/expenses records who paid and splits it equally, by exact amounts, or by shares, always adding up to the paisa. GET /groups/{id}/settle-up shows each member's balance and the payments that clear them.

An everyday analogy

A family shares 10 mangoes among 3 children: each gets 3, and the 10th goes to the youngest, because that is the family rule. Nobody cuts the mango into 3.33 pieces and throws away the crumbs.

How it works in 4 steps

  1. Record an expense: who paid, how many paise, and how to split.
  2. Split in whole paise; the leftover paise go out one at a time by a fixed rule.
  3. Keep the split with the expense, so balances never divide again.
  4. Settle up: net balances, then the biggest debtor pays the biggest creditor, again and again.
Check yourself: why not just round ₹333.333 up to ₹333.34 for everyone?

Then three people owe ₹1,000.02: two paise more than Asha paid. Rounding every share the same way, up or down, never adds up in general. Only giving out the remainder one paisa at a time does.

What this station is not

  • No real payments. Settle-up only suggests transfers.
  • No login, no database. Two groups are fixed in code.
  • Not the fewest possible payments in every case. The rule guarantees at most one fewer payment than people; the true minimum is a much harder problem.

Business problem

SplitSaathi (a fictional bill-splitting app) divides expenses with double and rounds each share. Totals drift by a paisa, so the person who paid is always slightly short, and support gets "the numbers don't add up" tickets. Settle-up replays every expense separately, so a weekend trip ends with a dozen transfers.

Acceptance criteria

  1. Given ₹1,000 split equally among three, then the shares are 33,334, 33,333 and 33,333 paise: the first person listed takes the extra paisa.
  2. Given shares 2:1:1 of ₹1,000, then 50,000, 25,000, 25,000.
  3. Given exact amounts that do not add up to the total, then 422 saying by how much.
  4. Given anyone outside the group, a person listed twice, or a zero share, then 422.
  5. Given a trip's expenses among four people, then settle-up needs at most 3 payments, and making them clears every balance.
  6. Given 1,000 random splits, then every one adds up exactly.

Requirements

  • All amounts are whole paise; ₹0.01 to ₹1,00,000 per expense (a demo rule). Fractions are 400.
  • Equal split: leftover paise go to the participants in the order listed.
  • Shares: largest-remainder method; ties go in the order listed.
  • Balances always add up to zero; settle-up refuses to run if they do not.

Learning objectives

  • Divide money and distribute the remainder so parts add up.
  • Explain why double, and BigDecimal with per-share rounding, both lose paise.
  • Implement equal, exact and share-based splits.
  • Net balances with a Map and settle with a greedy algorithm, and state its guarantee.
  • Test a rule on a thousand generated cases, not just three hand-picked ones.

The trap

Plausible but wrong

Dividing with double or default rounding, so a paisa goes missing.

"Divide and round to two decimals" looks careful. The first test shows ₹333.33 × 3 = ₹999.99. The second shows that BigDecimal alone is not the fix: dividing ₹1,000 by 3 exactly throws an exception, and rounding each share still loses the paisa. The third test shows the real splitter handing the leftover paisa to the first person. Dropping that leftover paisa from the code was tried while building: 2 tests went red.

package com.splitsaathi.groups;

import org.junit.jupiter.api.Test;

import java.math.BigDecimal;
import java.math.RoundingMode;
import java.util.List;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;

/**
 * The first test written for this station: it reproduces the bug before the fix.
 * Asha pays Rs 1,000 for dinner for three people.
 */
class MissingPaisaTrapTest extends ApiTest {

    /** The "before" split: divide in double, round each share to 2 decimals. Kept only in tests. */
    static double oldShare(double total, int people) {
        return Math.round(total / people * 100) / 100.0;
    }

    @Test
    void roundingEachShareSeparatelyLosesAPaisa() {
        double share = oldShare(1000.00, 3);
        assertThat(share).isEqualTo(333.33);
        assertThat(share * 3).isNotEqualTo(1000.00);   // 999.99: one paisa nobody owes, and Asha is out of pocket
    }

    @Test
    void bigDecimalDoesNotSaveYouByItself() {
        BigDecimal total = new BigDecimal("1000.00");
        // An exact division that never ends is refused...
        assertThatThrownBy(() -> total.divide(BigDecimal.valueOf(3))).isInstanceOf(ArithmeticException.class);
        // ...and rounding each share still loses the paisa. The remainder has to be handed out on purpose.
        BigDecimal share = total.divide(BigDecimal.valueOf(3), 2, RoundingMode.HALF_UP);
        assertThat(share.multiply(BigDecimal.valueOf(3))).isEqualByComparingTo("999.99");
    }

    @Test
    void theSplitterHandsTheLeftoverPaisaToSomeone() throws Exception {
        assertThat(Splitter.equal(100_000, List.of("asha", "ravi", "meera")).values()).containsExactly(33_334L, 33_333L, 33_333L);
        expense(1, """
                {"description":"Dinner","paidBy":"asha","amountPaise":100000,"splitType":"EQUAL","participants":["asha","ravi","meera"]}""")
                .andExpect(jsonPath("$.owedPaise.asha").value(33334))
                .andExpect(jsonPath("$.owedPaise.ravi").value(33333))
                .andExpect(jsonPath("$.owedPaise.meera").value(33333));
    }
}

package com.splitsaathi.groups;

import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestController;

import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

@RestController
class GroupController {

    record SettleUpView(long groupId, Map<String, Long> balancesPaise, List<SettleUp.Payment> payments) {
    }

    private final Groups groups;

    GroupController(Groups groups) {
        this.groups = groups;
    }

    @PostMapping("/groups/{id}/expenses")
    @ResponseStatus(HttpStatus.CREATED)
    Groups.Expense add(@PathVariable long id, @Valid @RequestBody ExpenseRequest r) {
        Groups.Group g = group(id);
        member(g, r.paidBy());
        Map<String, Long> owed = switch (r.splitType()) {
            case EQUAL -> {
                if (r.participants() == null || r.participants().isEmpty()) {
                    throw unprocessable("EQUAL needs a non-empty participants list.");
                }
                r.participants().forEach(p -> member(g, p));
                if (r.participants().stream().distinct().count() != r.participants().size()) {
                    throw unprocessable("Each participant can be listed once.");
                }
                yield Splitter.equal(r.amountPaise(), r.participants());
            }
            case EXACT -> {
                if (r.exactPaise() == null || r.exactPaise().isEmpty()) {
                    throw unprocessable("EXACT needs exactPaise for each person.");
                }
                r.exactPaise().forEach((p, v) -> {
                    member(g, p);
                    if (v == null || v < 0) {
                        throw unprocessable("Each exact amount must be zero or more.");
                    }
                });
                long sum = r.exactPaise().values().stream().mapToLong(Long::longValue).sum();
                if (sum != r.amountPaise()) {
                    throw unprocessable("The exact amounts add up to " + sum + " paise, not " + r.amountPaise() + ".");
                }
                yield new LinkedHashMap<>(r.exactPaise()); // keeps the order people were listed in
            }
            case SHARES -> {
                if (r.shares() == null || r.shares().isEmpty()) {
                    throw unprocessable("SHARES needs a share for each person.");
                }
                r.shares().forEach((p, s) -> {
                    member(g, p);
                    if (s == null || s < 1 || s > 1000) {
                        throw unprocessable("Each share must be from 1 to 1000.");
                    }
                });
                yield Splitter.shares(r.amountPaise(), r.shares());
            }
        };
        return groups.add(g, r.description(), r.paidBy(), r.amountPaise(), owed);
    }

    @GetMapping("/groups/{id}/settle-up")
    SettleUpView settleUp(@PathVariable long id) {
        Groups.Group g = group(id);
        Map<String, Long> balances = groups.balances(g);
        return new SettleUpView(id, balances, SettleUp.payments(balances));
    }

    private Groups.Group group(long id) {
        return groups.find(id).orElseThrow(() -> problem(HttpStatus.NOT_FOUND, "Group not found", "No group has this id."));
    }

    private static void member(Groups.Group g, String name) {
        if (!g.members().contains(name)) {
            throw unprocessable("Everyone in an expense must be a member of the group.");
        }
    }

    private static ErrorResponseException unprocessable(String detail) {
        return problem(HttpStatus.UNPROCESSABLE_CONTENT, "Invalid split", detail);
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setTitle(title);
        return new ErrorResponseException(status, p, null);
    }
}

src/main/java/com/splitsaathi/groups/Splitter.java

Does
Equal and share-based splits in whole paise that always add up.
Why
The money rule lives in one small, heavily tested class.
Without it
The trap: rounded shares that do not add up.
  • total / n and total % n: the quotient and the remainder, in exact integers.
  • Shares: whole part first, then the leftover paise to the biggest cut-off fractions.
package com.splitsaathi.groups;

import java.util.ArrayList;
import java.util.Comparator;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

/**
 * Splits an amount in whole paise so the parts always add up to the total: no paisa lost, none invented.
 * Division leaves a remainder; the remainder is handed out one paisa at a time, by a fixed rule, so the same
 * expense always splits the same way.
 */
final class Splitter {

    private Splitter() {
    }

    /** Rs 1,000 among 3: 33,333 paise each and 1 left over, which goes to the first person listed. */
    static Map<String, Long> equal(long totalPaise, List<String> people) {
        long each = totalPaise / people.size();
        long remainder = totalPaise % people.size();
        Map<String, Long> owed = new LinkedHashMap<>();
        for (int i = 0; i < people.size(); i++) {
            owed.put(people.get(i), each + (i < remainder ? 1 : 0));
        }
        return owed;
    }

    /**
     * Shares like 2:1:1. Each person first gets the whole paise of their exact share; the paise left over go one each
     * to the people whose exact share had the largest fraction cut off (ties: the order listed). This is the
     * "largest remainder" method.
     */
    static Map<String, Long> shares(long totalPaise, Map<String, Integer> shares) {
        long sum = shares.values().stream().mapToLong(Integer::longValue).sum();
        Map<String, Long> owed = new LinkedHashMap<>();
        List<Map.Entry<String, Long>> cutOff = new ArrayList<>(); // person -> remainder of totalPaise * share / sum
        long given = 0;
        for (Map.Entry<String, Integer> s : shares.entrySet()) {
            long exact = totalPaise * s.getValue();
            owed.put(s.getKey(), exact / sum);
            cutOff.add(Map.entry(s.getKey(), exact % sum));
            given += exact / sum;
        }
        cutOff.sort(Map.Entry.<String, Long>comparingByValue(Comparator.reverseOrder())); // stable: ties keep listed order
        for (int i = 0; i < totalPaise - given; i++) {
            owed.merge(cutOff.get(i).getKey(), 1L, Long::sum);
        }
        return owed;
    }
}

src/main/java/com/splitsaathi/groups/SettleUp.java

Does
Greedy settle-up: biggest debtor pays biggest creditor until all are zero.
Why
Each payment clears at least one person: at most n − 1 payments.
Without it
One payment per person per expense.
  • Refuses balances that do not add up to zero: a bug elsewhere must not become wrong payments.
  • A TreeMap makes ties resolve the same way every time.
package com.splitsaathi.groups;

import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;

/**
 * Turns net balances into payments. Greedy: the person who owes the most pays the person owed the most, as much as
 * one of them needs; repeat. Each payment settles at least one person, so n people need at most n - 1 payments.
 * (The true minimum is a much harder problem in general; this bound is what apps like this use in practice.)
 */
final class SettleUp {

    record Payment(String from, String to, long amountPaise) {
    }

    private SettleUp() {
    }

    /** balances: positive = is owed money, negative = owes money. They must add up to zero. */
    static List<Payment> payments(Map<String, Long> balances) {
        if (balances.values().stream().mapToLong(Long::longValue).sum() != 0) {
            throw new IllegalStateException("balances do not add up to zero");
        }
        Map<String, Long> left = new TreeMap<>(balances); // sorted by name, so ties always resolve the same way
        List<Payment> payments = new ArrayList<>();
        while (true) {
            var debtor = left.entrySet().stream().min(Comparator.comparingLong(Map.Entry::getValue)).orElseThrow();
            var creditor = left.entrySet().stream().max(Comparator.comparingLong(Map.Entry::getValue)).orElseThrow();
            if (creditor.getValue() == 0) {
                return payments;
            }
            long amount = Math.min(-debtor.getValue(), creditor.getValue());
            payments.add(new Payment(debtor.getKey(), creditor.getKey(), amount));
            left.put(debtor.getKey(), debtor.getValue() + amount);
            left.put(creditor.getKey(), creditor.getValue() - amount);
        }
    }
}

    }

    private final Map<Long, Group> groups = Map.of(
            1L, new Group(1, "Goa trip", List.of("asha", "kabir", "meera", "ravi"), new ArrayList<>()),
            2L, new Group(2, "Flat 302", List.of("neha", "omar"), new ArrayList<>()));

    Optional<Group> find(long id) {
        return Optional.ofNullable(groups.get(id));
    }

    synchronized Expense add(Group g, String description, String paidBy, long amountPaise, Map<String, Long> owed) {
        Expense e = new Expense(UUID.randomUUID(), description, paidBy, amountPaise, owed);
        g.expenses().add(e);
        return e;
    }

    /** Net balance per member: what they paid minus what they owe. Positive: others owe them. Always sums to zero. */
    synchronized Map<String, Long> balances(Group g) {
        Map<String, Long> net = new LinkedHashMap<>();
        g.members().forEach(m -> net.put(m, 0L));
        for (Expense e : g.expenses()) {
            net.merge(e.paidBy(), e.amountPaise(), Long::sum);
            e.owedPaise().forEach((who, owes) -> net.merge(who, -owes, Long::sum));
        }
        return net;
    }

    /** For tests only. */
    synchronized void clear() {
        groups.values().forEach(g -> g.expenses().clear());
    }
}

package com.splitsaathi.groups;

import org.junit.jupiter.api.Test;

import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Random;

import static org.assertj.core.api.Assertions.assertThat;

/** The money rules on their own: parts always add up, and settle-up always clears every balance. */
class SplitterTest {

    @Test
    void sharesUseTheLargestRemainder() {
        Map<String, Integer> shares = new LinkedHashMap<>();
        shares.put("a", 1);
        shares.put("b", 1);
        shares.put("c", 1);
        assertThat(Splitter.shares(10_000, shares).values()).containsExactly(3_334L, 3_333L, 3_333L);
        shares.put("c", 2);  // 1:1:2 of 101 paise -> 25.25, 25.25, 50.5: the half paisa goes to c
        assertThat(Splitter.shares(101, shares).values()).containsExactly(25L, 25L, 51L);
    }

    @Test
    void aThousandRandomSplitsAllAddUpExactly() {
        Random random = new Random(42); // fixed seed: the same 1,000 cases every run
        for (int i = 0; i < 1_000; i++) {
            long total = 1 + random.nextInt(10_000_000);
            int people = 1 + random.nextInt(12);
            List<String> names = new ArrayList<>();
            Map<String, Integer> shares = new LinkedHashMap<>();
            for (int p = 0; p < people; p++) {
                names.add("p" + p);
                shares.put("p" + p, 1 + random.nextInt(5));
            }
            Map<String, Long> equal = Splitter.equal(total, names);
            assertThat(equal.values().stream().mapToLong(Long::longValue).sum()).isEqualTo(total);
            assertThat(equal.values().stream().mapToLong(Long::longValue).max().orElseThrow()
                    - equal.values().stream().mapToLong(Long::longValue).min().orElseThrow()).isLessThanOrEqualTo(1);
            assertThat(Splitter.shares(total, shares).values().stream().mapToLong(Long::longValue).sum()).isEqualTo(total);
        }
    }

    @Test
    void settleUpClearsEveryBalanceInAtMostNMinusOnePayments() {
        Map<String, Long> balances = new LinkedHashMap<>();
        balances.put("asha", 50_000L);
        balances.put("kabir", -20_000L);
        balances.put("meera", -10_000L);
        balances.put("ravi", -20_000L);
        var payments = SettleUp.payments(balances);
        assertThat(payments).hasSizeLessThanOrEqualTo(3);
        Map<String, Long> after = new LinkedHashMap<>(balances);
        payments.forEach(p -> {
            after.merge(p.from(), p.amountPaise(), Long::sum);
            after.merge(p.to(), -p.amountPaise(), Long::sum);
        });
        assertThat(after.values()).containsOnly(0L);
    }
}

package com.splitsaathi.groups;

import jakarta.validation.Valid;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestController;

import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

@RestController
class GroupController {

    record SettleUpView(long groupId, Map<String, Long> balancesPaise, List<SettleUp.Payment> payments) {
    }

    private final Groups groups;

    GroupController(Groups groups) {
        this.groups = groups;
    }

    @PostMapping("/groups/{id}/expenses")
    @ResponseStatus(HttpStatus.CREATED)
    Groups.Expense add(@PathVariable long id, @Valid @RequestBody ExpenseRequest r) {
        Groups.Group g = group(id);
        member(g, r.paidBy());
        Map<String, Long> owed = switch (r.splitType()) {
            case EQUAL -> {
                if (r.participants() == null || r.participants().isEmpty()) {
                    throw unprocessable("EQUAL needs a non-empty participants list.");
                }
                r.participants().forEach(p -> member(g, p));
                if (r.participants().stream().distinct().count() != r.participants().size()) {
                    throw unprocessable("Each participant can be listed once.");
                }
                yield Splitter.equal(r.amountPaise(), r.participants());
            }
            case EXACT -> {
                if (r.exactPaise() == null || r.exactPaise().isEmpty()) {
                    throw unprocessable("EXACT needs exactPaise for each person.");
                }
                r.exactPaise().forEach((p, v) -> {
                    member(g, p);
                    if (v == null || v < 0) {
                        throw unprocessable("Each exact amount must be zero or more.");
                    }
                });
                long sum = r.exactPaise().values().stream().mapToLong(Long::longValue).sum();
                if (sum != r.amountPaise()) {
                    throw unprocessable("The exact amounts add up to " + sum + " paise, not " + r.amountPaise() + ".");
                }
                yield new LinkedHashMap<>(r.exactPaise()); // keeps the order people were listed in
            }
            case SHARES -> {
                if (r.shares() == null || r.shares().isEmpty()) {
                    throw unprocessable("SHARES needs a share for each person.");
                }
                r.shares().forEach((p, s) -> {
                    member(g, p);
                    if (s == null || s < 1 || s > 1000) {
                        throw unprocessable("Each share must be from 1 to 1000.");
                    }
                });
                yield Splitter.shares(r.amountPaise(), r.shares());
            }
            // Challenge 1: percentages are shares that must add up to 100, so the same largest-remainder split applies.
            case PERCENT -> {
                if (r.percents() == null || r.percents().isEmpty()) {
                    throw unprocessable("PERCENT needs a percentage for each person.");
                }
                r.percents().forEach((p, pct) -> {
                    member(g, p);
                    if (pct == null || pct < 1) {
                        throw unprocessable("Each percentage must be at least 1.");
                    }
                });
                if (r.percents().values().stream().mapToInt(Integer::intValue).sum() != 100) {
                    throw unprocessable("The percentages must add up to 100.");
                }
                yield Splitter.shares(r.amountPaise(), r.percents());
            }
        };
        return groups.add(g, r.description(), r.paidBy(), r.amountPaise(), owed);
    }

    /** Challenge 2. */
    record Settlement(@NotBlank String from, @NotBlank String to, @NotNull @Min(1) Long amountPaise) {
    }

    /**
     * Challenge 2: "Ravi paid Asha Rs 300" is, for the balances, an expense Ravi paid that Asha alone owes:
     * Ravi's balance goes up by 300, Asha's goes down by 300. No new kind of record is needed.
     */
    @PostMapping("/groups/{id}/settlements")
    @ResponseStatus(HttpStatus.CREATED)
    Groups.Expense settle(@PathVariable long id, @Valid @RequestBody Settlement s) {
        Groups.Group g = group(id);
        member(g, s.from());
        member(g, s.to());
        if (s.from().equals(s.to())) {
            throw unprocessable("A settlement is between two different members.");
        }
        return groups.add(g, "Settlement", s.from(), s.amountPaise(), Map.of(s.to(), s.amountPaise()));
    }

    @GetMapping("/groups/{id}/settle-up")
    SettleUpView settleUp(@PathVariable long id) {
        Groups.Group g = group(id);
        Map<String, Long> balances = groups.balances(g);
        return new SettleUpView(id, balances, SettleUp.payments(balances));
    }

    private Groups.Group group(long id) {
        return groups.find(id).orElseThrow(() -> problem(HttpStatus.NOT_FOUND, "Group not found", "No group has this id."));
    }

    private static void member(Groups.Group g, String name) {
        if (!g.members().contains(name)) {
            throw unprocessable("Everyone in an expense must be a member of the group.");
        }
    }

    private static ErrorResponseException unprocessable(String detail) {
        return problem(HttpStatus.UNPROCESSABLE_CONTENT, "Invalid split", detail);
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setTitle(title);
        return new ErrorResponseException(status, p, null);
    }
}

package com.splitsaathi.groups;

import jakarta.validation.Valid;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestController;

import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

@RestController
class GroupController {

    record SettleUpView(long groupId, Map<String, Long> balancesPaise, List<SettleUp.Payment> payments) {
    }

    private final Groups groups;

    GroupController(Groups groups) {
        this.groups = groups;
    }

    @PostMapping("/groups/{id}/expenses")
    @ResponseStatus(HttpStatus.CREATED)
    Groups.Expense add(@PathVariable long id, @Valid @RequestBody ExpenseRequest r) {
        Groups.Group g = group(id);
        member(g, r.paidBy());
        Map<String, Long> owed = switch (r.splitType()) {
            case EQUAL -> {
                if (r.participants() == null || r.participants().isEmpty()) {
                    throw unprocessable("EQUAL needs a non-empty participants list.");
                }
                r.participants().forEach(p -> member(g, p));
                if (r.participants().stream().distinct().count() != r.participants().size()) {
                    throw unprocessable("Each participant can be listed once.");
                }
                yield Splitter.equal(r.amountPaise(), r.participants());
            }
            case EXACT -> {
                if (r.exactPaise() == null || r.exactPaise().isEmpty()) {
                    throw unprocessable("EXACT needs exactPaise for each person.");
                }
                r.exactPaise().forEach((p, v) -> {
                    member(g, p);
                    if (v == null || v < 0) {
                        throw unprocessable("Each exact amount must be zero or more.");
                    }
                });
                long sum = r.exactPaise().values().stream().mapToLong(Long::longValue).sum();
                if (sum != r.amountPaise()) {
                    throw unprocessable("The exact amounts add up to " + sum + " paise, not " + r.amountPaise() + ".");
                }
                yield new LinkedHashMap<>(r.exactPaise()); // keeps the order people were listed in
            }
            case SHARES -> {
                if (r.shares() == null || r.shares().isEmpty()) {
                    throw unprocessable("SHARES needs a share for each person.");
                }
                r.shares().forEach((p, s) -> {
                    member(g, p);
                    if (s == null || s < 1 || s > 1000) {
                        throw unprocessable("Each share must be from 1 to 1000.");
                    }
                });
                yield Splitter.shares(r.amountPaise(), r.shares());
            }
            // Challenge 1: percentages are shares that must add up to 100, so the same largest-remainder split applies.
            case PERCENT -> {
                if (r.percents() == null || r.percents().isEmpty()) {
                    throw unprocessable("PERCENT needs a percentage for each person.");
                }
                r.percents().forEach((p, pct) -> {
                    member(g, p);
                    if (pct == null || pct < 1) {
                        throw unprocessable("Each percentage must be at least 1.");
                    }
                });
                if (r.percents().values().stream().mapToInt(Integer::intValue).sum() != 100) {
                    throw unprocessable("The percentages must add up to 100.");
                }
                yield Splitter.shares(r.amountPaise(), r.percents());
            }
        };
        return groups.add(g, r.description(), r.paidBy(), r.amountPaise(), owed);
    }

    /** Challenge 2. */
    record Settlement(@NotBlank String from, @NotBlank String to, @NotNull @Min(1) Long amountPaise) {
    }

    /**
     * Challenge 2: "Ravi paid Asha Rs 300" is, for the balances, an expense Ravi paid that Asha alone owes:
     * Ravi's balance goes up by 300, Asha's goes down by 300. No new kind of record is needed.
     */
    @PostMapping("/groups/{id}/settlements")
    @ResponseStatus(HttpStatus.CREATED)
    Groups.Expense settle(@PathVariable long id, @Valid @RequestBody Settlement s) {
        Groups.Group g = group(id);
        member(g, s.from());
        member(g, s.to());
        if (s.from().equals(s.to())) {
            throw unprocessable("A settlement is between two different members.");
        }
        return groups.add(g, "Settlement", s.from(), s.amountPaise(), Map.of(s.to(), s.amountPaise()));
    }

    @GetMapping("/groups/{id}/settle-up")
    SettleUpView settleUp(@PathVariable long id) {
        Groups.Group g = group(id);
        Map<String, Long> balances = groups.balances(g);
        return new SettleUpView(id, balances, SettleUp.payments(balances));
    }

    private Groups.Group group(long id) {
        return groups.find(id).orElseThrow(() -> problem(HttpStatus.NOT_FOUND, "Group not found", "No group has this id."));
    }

    private static void member(Groups.Group g, String name) {
        if (!g.members().contains(name)) {
            throw unprocessable("Everyone in an expense must be a member of the group.");
        }
    }

    private static ErrorResponseException unprocessable(String detail) {
        return problem(HttpStatus.UNPROCESSABLE_CONTENT, "Invalid split", detail);
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setTitle(title);
        return new ErrorResponseException(status, p, null);
    }
}

Implementation approach

  1. Write the trap test: double and rounded BigDecimal both lose a paisa.
  2. Write the splitter in whole paise, with a fixed remainder rule; test it on 1,000 generated cases.
  3. Store each expense's split; compute balances by adding paid and subtracting owed.
  4. Write the greedy settle-up and prove it clears every balance.

Interview takeaways

How do you split ₹1,000 three ways so it adds up?

Work in paise: 100,000 ÷ 3 = 33,333 remainder 1. Give everyone 33,333 and the leftover paisa to one person by a fixed rule. Shares are 33,334, 33,333 and 33,333.

Does BigDecimal fix rounding problems?

It fixes representation (0.1 is exact), not allocation. Dividing 1000 by 3 exactly throws; rounding each share to two decimals still loses a paisa. You must distribute the remainder.

What is the largest remainder method?

Give everyone the whole part of their exact share, then hand the leftover units, one each, to those whose fractions were largest.

How many payments does greedy settle-up need?

At most n − 1 for n people, because each payment brings at least one person to zero. The true minimum can be lower and is expensive to find in general.

Why test with 1,000 random cases?

Hand-picked examples confirm what you already thought of. Generated cases, with a fixed seed so failures repeat, check the invariant everywhere: parts always add up to the total.
