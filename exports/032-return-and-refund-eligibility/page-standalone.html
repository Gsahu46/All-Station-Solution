Level 1, about 5 minutes. Plain language: no code.

The problem in real life

  1. A rule changes

    Electronics returns go from 30 days to 7. A developer edits the switch statement, runs the one test (an electronics return on day 3), sees green, and ships.

  2. Something else breaks

    Clothing shared that case of the switch. Customers returning a kurta on day 10 are refused. Support finds out from complaints.

  3. The fix

    Each category owns its window. The rules become one function tested with a table: every category, every reason, the last day and the day after.

A test suite that checks only what you changed cannot see what you broke.

What are we building?

POST /refund-eligibility-checks answers, before a customer books a pickup: can this order be returned for this reason, how much comes back, and until which day? If not, it lists every reason.

An everyday analogy

A shop's returns desk with a printed rule card per department. Changing the electronics card cannot change the clothing card, and the manager tests a new card against a list of real situations, not just one.

How it works in 4 steps

  1. Find the order and its category, price and delivery date.
  2. Find today in India's calendar.
  3. Apply the rules: window, accepted reasons, hygiene items, tags, seal.
  4. Answer and record: eligible or every reason why not, the refund, the last day.
Check yourself: the old suite had one test and it passed after the change. What would have caught the bug?

Any test of a clothing return between day 8 and day 30. A table with one row per category at its last day would have turned red the moment clothing's window changed.

What this station is not

  • No refunds. A check only: no money moves, no pickup is booked.
  • One item per order. Real orders have many lines, each checked the same way.
  • No database. Demo orders in memory.

Business problem

Kartwala (a fictional shopping app) has refund rules with many conditions and no tests but one. A change for electronics broke refunds for clothing, and no test noticed.

The rules (demo)

CategoryWindow after deliveryAccepted reasonsExtra conditions
Clothing30 daysAll fiveInnerwear: only damaged or wrong item. Changed mind or size: tags attached.
Electronics7 daysDamaged, wrong item, not as describedSeal broken: only damaged.
Books10 daysDamaged, wrong item, changed mind
Grocery2 daysDamaged, wrong item

Changed mind and size issue are the customer's choice: ₹49 pickup fee is deducted. For damaged, wrong or not-as-described items, the full price comes back. Not delivered yet: nothing to return (cancel instead).

Acceptance criteria

  1. Given a kurta delivered 14 days ago that did not fit, tags attached, then eligible, ₹1,250.00 back (₹1,299 minus ₹49), last day 16 days from now.
  2. Given earbuds delivered 9 days ago, changed mind, seal broken, then refused for all three reasons: WINDOW_CLOSED, REASON_NOT_ACCEPTED, SEAL_BROKEN.
  3. Given the last day of any category's window, then open; the day after, closed.
  4. Given 01:30 in India on the day after the last day (still the last day on a UTC server), then closed.
  5. Given clothing without a tagsAttached answer, or electronics without sealIntact, then 400.
  6. Given an unknown order, 404; an unknown reason or field, 400.

Requirements

  • Each category owns its window and reasons; no rule is shared by accident.
  • The rules are a pure function; "today" comes from a Clock, in India's time zone.
  • Every decision is recorded for support.
  • Money in integer paise; a refund is never negative.

Learning objectives

  • Write table-driven tests with @ParameterizedTest, @CsvSource and @EnumSource.
  • Know when to stub and when to verify with Mockito.
  • Use AssertJ for readable assertions.
  • Make time testable with a Clock.
  • Shape code so the important part is easy to test.

The trap

Plausible but wrong

Testing only the happy path: one changed rule breaks another category unnoticed.

The test file rebuilds the old switch, where clothing and electronics shared a case. The old suite's only test, an electronics return on day 3, still passes against it. A clothing return on day 20 is refused by it, and accepted by the new rules. While building, each fix was undone once. Clothing back at 7 days turned 5 tests red. Dropping the hygiene rule turned 3 red, and counting days on the server's date instead of India's turned 1 red. Charging the fee for every reason turned 2 red, not recording the decision 1, and letting a broken seal block a damaged phone 2. Listing only the first reason turned 2 red.

package com.kartwala.refunds;

import org.junit.jupiter.api.Test;

import java.time.LocalDate;

import static org.assertj.core.api.Assertions.assertThat;

/** The first test written for this station: the old suite had one happy-path test, and it never noticed. */
class HappyPathOnlyTrapTest {

    static final LocalDate TODAY = LocalDate.of(2026, 10, 15);

    @Test
    void theOldSuitesOnlyTestStillPassedAfterTheChange() {
        // The test that existed: electronics, three days after delivery. Green before and after the March change.
        assertThat(OldRefundRules.withinWindow(Category.ELECTRONICS, 3)).isTrue();
    }

    @Test
    void butClothingReturnedOnDay20WasRefusedByTheOldRule() {
        assertThat(OldRefundRules.withinWindow(Category.CLOTHING, 20)).isFalse();   // the bug customers hit
        Order kurta = new Order("KW-1001", "Cotton kurta", Category.CLOTHING, 129_900, TODAY.minusDays(20), false);
        RefundRules.Decision now = RefundRules.check(kurta, Reason.SIZE_ISSUE, true, null, TODAY);
        assertThat(now.eligible()).isTrue();
        assertThat(now.lastDayToReturn()).isEqualTo(TODAY.plusDays(10));
    }

    @Test
    void electronicsKeepsItsSevenDaysSoTheFixDidNotUndoTheChange() {
        Order phone = new Order("KW-1004", "Smartphone", Category.ELECTRONICS, 1_899_900, TODAY.minusDays(8), false);
        assertThat(RefundRules.check(phone, Reason.DAMAGED, null, true, TODAY).reasons()).containsExactly("WINDOW_CLOSED");
    }
}
package com.kartwala.refunds;

/**
 * The window rule as it was before the fix, kept only in tests. Clothing and electronics shared one case of a switch.
 * In March electronics moved from 30 days to 7: the change was made in the shared case, so clothing moved too.
 */
final class OldRefundRules {

    private OldRefundRules() {
    }

    static int windowDays(Category category) {
        switch (category) {
            case CLOTHING:
            case ELECTRONICS:
                return 7;   // was 30 for both; "electronics only" was the intent
            case BOOKS:
                return 10;
            default:
                return 2;
        }
    }

    static boolean withinWindow(Category category, int daysSinceDelivery) {
        return daysSinceDelivery <= windowDays(category);
    }
}

package com.kartwala.refunds;

import jakarta.validation.Valid;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Pattern;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

import java.time.LocalDate;
import java.util.List;
import java.util.Locale;

@RestController
class RefundController {

    /** tagsAttached is asked for clothing, sealIntact for electronics; otherwise they may be left out. */
    record CheckRequest(@NotNull @Pattern(regexp = "(?i)KW-\\d{4}", message = "must look like KW-1001") String orderId,
                        @NotNull Reason reason, Boolean tagsAttached, Boolean sealIntact) {
    }

    record CheckResponse(String orderId, boolean eligible, List<String> reasons, long refundPaise, LocalDate lastDayToReturn) {
    }

    private final RefundService service;

    RefundController(RefundService service) {
        this.service = service;
    }

    /** A check only: nothing is returned or refunded by calling it. */
    @PostMapping("/refund-eligibility-checks")
    CheckResponse check(@Valid @RequestBody CheckRequest request) {
        RefundRules.Decision d = service.check(request.orderId(), request.reason(), request.tagsAttached(), request.sealIntact());
        return new CheckResponse(request.orderId().toUpperCase(Locale.ROOT), d.eligible(), d.reasons(), d.refundPaise(), d.lastDayToReturn());
    }
}

package com.kartwala.refunds;

import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.stereotype.Service;
import org.springframework.web.ErrorResponseException;

import java.time.Clock;
import java.time.LocalDate;
import java.time.ZoneId;
import java.util.Locale;

/** Looks up the order, asks the rules, records the decision. The only place that knows what "today" is. */
@Service
class RefundService {

    static final ZoneId INDIA = ZoneId.of("Asia/Kolkata");

    private final OrderLookup orders;
    private final EligibilityAudit audit;
    private final Clock clock;

    RefundService(OrderLookup orders, EligibilityAudit audit, Clock clock) {
        this.orders = orders;
        this.audit = audit;
        this.clock = clock;
    }

    /** Return windows are counted in the customer's calendar: at 01:30 in India it is already tomorrow. */
    static LocalDate today(Clock clock) {
        return LocalDate.now(clock.withZone(INDIA));
    }

    RefundRules.Decision check(String rawOrderId, Reason reason, Boolean tagsAttached, Boolean sealIntact) {
        String orderId = rawOrderId.toUpperCase(Locale.ROOT);
        Order order = orders.find(orderId).orElseThrow(() -> problem(HttpStatus.NOT_FOUND, "Order not found", "No order " + orderId + "."));
        if (order.category() == Category.CLOTHING && tagsAttached == null) {
            throw problem(HttpStatus.BAD_REQUEST, "Missing answer", "tagsAttached is required for clothing.");
        }
        if (order.category() == Category.ELECTRONICS && sealIntact == null) {
            throw problem(HttpStatus.BAD_REQUEST, "Missing answer", "sealIntact is required for electronics.");
        }
        RefundRules.Decision decision = RefundRules.check(order, reason, tagsAttached, sealIntact, today(clock));
        audit.record(orderId, reason, decision);
        return decision;
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setTitle(title);
        return new ErrorResponseException(status, p, null);
    }
}

Why

package com.kartwala.refunds;

import java.time.LocalDate;
import java.util.ArrayList;
import java.util.List;

/**
 * The refund rules as one pure function: no Spring, no clock, no database. Everything it needs is a parameter, so a
 * table of cases can test every category and reason in milliseconds. Returns every reason a return is refused.
 */
final class RefundRules {

    /** Demo rule: a return the customer chose (changed mind, size) pays ₹49 for the pickup. */
    static final long PICKUP_FEE_PAISE = 4_900;

    record Decision(boolean eligible, List<String> reasons, long refundPaise, LocalDate lastDayToReturn) {
    }

    private RefundRules() {
    }

    static Decision check(Order order, Reason reason, Boolean tagsAttached, Boolean sealIntact, LocalDate today) {
        if (order.deliveredOn() == null) {
            return new Decision(false, List.of("NOT_DELIVERED"), 0, null);   // nothing to return yet: cancel instead
        }
        Category category = order.category();
        LocalDate lastDay = order.deliveredOn().plusDays(category.windowDays);
        List<String> refused = new ArrayList<>();
        if (today.isAfter(lastDay)) {
            refused.add("WINDOW_CLOSED");
        }
        if (!category.reasons.contains(reason)) {
            refused.add("REASON_NOT_ACCEPTED");
        }
        if (category == Category.CLOTHING) {
            if (order.hygieneItem() && reason != Reason.DAMAGED && reason != Reason.WRONG_ITEM) {
                refused.add("HYGIENE_ITEM");
            }
            if (!tagsAttached && reason.customersChoice) {
                refused.add("TAGS_REMOVED");
            }
        }
        if (category == Category.ELECTRONICS && !sealIntact && reason != Reason.DAMAGED) {
            refused.add("SEAL_BROKEN");
        }
        if (!refused.isEmpty()) {
            return new Decision(false, List.copyOf(refused), 0, lastDay);
        }
        long fee = reason.customersChoice ? PICKUP_FEE_PAISE : 0;
        return new Decision(true, List.of(), Math.max(0, order.pricePaise() - fee), lastDay);
    }
}

package com.kartwala.refunds;

import java.util.EnumSet;
import java.util.Set;

import static com.kartwala.refunds.Reason.CHANGED_MIND;
import static com.kartwala.refunds.Reason.DAMAGED;
import static com.kartwala.refunds.Reason.NOT_AS_DESCRIBED;
import static com.kartwala.refunds.Reason.SIZE_ISSUE;
import static com.kartwala.refunds.Reason.WRONG_ITEM;

/**
 * Each category's return window and accepted reasons, in one place (demo rules). The window and the reasons belong
 * to the category: changing electronics cannot change clothing, which is how the old switch statement broke it.
 */
enum Category {
    CLOTHING(30, EnumSet.of(DAMAGED, WRONG_ITEM, NOT_AS_DESCRIBED, CHANGED_MIND, SIZE_ISSUE)),
    ELECTRONICS(7, EnumSet.of(DAMAGED, WRONG_ITEM, NOT_AS_DESCRIBED)),
    BOOKS(10, EnumSet.of(DAMAGED, WRONG_ITEM, CHANGED_MIND)),
    GROCERY(2, EnumSet.of(DAMAGED, WRONG_ITEM));

    final int windowDays;
    final Set<Reason> reasons;

    Category(int windowDays, Set<Reason> reasons) {
        this.windowDays = windowDays;
        this.reasons = reasons;
    }
}

/**
 * The service with Mockito, no Spring. Stub the query (OrderLookup: what it returns matters, how often it is called
 * does not), verify the command (EligibilityAudit: that it happened is the behaviour). Strict stubs are on, so a stub
 * the code never uses fails the test.

@ExtendWith(MockitoExtension.class)
class RefundServiceTest {

    // 20:00 UTC on 15 October is 01:30 on 16 October in India.
    static final Clock LATE_EVENING_UTC = Clock.fixed(Instant.parse("2026-10-15T20:00:00Z"), ZoneOffset.UTC);

    @Mock
    OrderLookup orders;
    @Mock
    EligibilityAudit audit;

        return new RefundService(orders, audit, LATE_EVENING_UTC);
    }

    @Test
    void theLastDayIsCountedInIndiaNotOnTheServer() {
        // Delivered 15 September: the 30-day window ends on 15 October. On the server it is still the 15th; in India
        // it is the 16th, and the customer's calendar decides.
        when(orders.find("KW-1001")).thenReturn(Optional.of(

        RefundRules.Decision d = service().check("kw-1001", Reason.SIZE_ISSUE, true, null);
        assertThat(d.reasons()).containsExactly("WINDOW_CLOSED");
        assertThat(d.lastDayToReturn()).isEqualTo(LocalDate.of(2026, 10, 15));
    }

    @Test
    void everyDecisionIsRecordedOnce() {
        when(orders.find("KW-1004")).thenReturn(Optional.of(
                new Order("KW-1004", "Smartphone", Category.ELECTRONICS, 1_899_900, LocalDate.of(2026, 10, 14), false)));

        verify(audit).record(eq("KW-1004"), eq(Reason.DAMAGED), recorded.capture());
        assertThat(recorded.getValue()).isEqualTo(d);
        assertThat(d.refundPaise()).isEqualTo(1_899_900);

    @Test
    void anUnknownOrderOrAMissingAnswerRecordsNothing() {
        when(orders.find("KW-9999")).thenReturn(Optional.empty());

                new Order("KW-1004", "Smartphone", Category.ELECTRONICS, 1_899_900, LocalDate.of(2026, 10, 14), false)));

package com.kartwala.refunds;

/**
 * The window rule as it was before the fix, kept only in tests. Clothing and electronics shared one case of a switch.
 * In March electronics moved from 30 days to 7: the change was made in the shared case, so clothing moved too.
 */
final class OldRefundRules {

    private OldRefundRules() {
    }

    static int windowDays(Category category) {
        switch (category) {
            case CLOTHING:
            case ELECTRONICS:
                return 7;   // was 30 for both; "electronics only" was the intent
            case BOOKS:
                return 10;
            default:
                return 2;
        }
    }

    static boolean withinWindow(Category category, int daysSinceDelivery) {
        return daysSinceDelivery <= windowDays(category);
    }
}

package com.kartwala.refunds;

import java.util.EnumSet;
import java.util.Set;

import static com.kartwala.refunds.Reason.CHANGED_MIND;
import static com.kartwala.refunds.Reason.DAMAGED;
import static com.kartwala.refunds.Reason.NOT_AS_DESCRIBED;
import static com.kartwala.refunds.Reason.SIZE_ISSUE;
import static com.kartwala.refunds.Reason.WRONG_ITEM;

/**
 * Each category's return window and accepted reasons, in one place (demo rules). The window and the reasons belong
 * to the category: changing electronics cannot change clothing, which is how the old switch statement broke it.
 */
enum Category {
    CLOTHING(30, EnumSet.of(DAMAGED, WRONG_ITEM, NOT_AS_DESCRIBED, CHANGED_MIND, SIZE_ISSUE)),
    ELECTRONICS(7, EnumSet.of(DAMAGED, WRONG_ITEM, NOT_AS_DESCRIBED)),
    BOOKS(10, EnumSet.of(DAMAGED, WRONG_ITEM, CHANGED_MIND)),
    GROCERY(2, EnumSet.of(DAMAGED, WRONG_ITEM)),
    FOOTWEAR(15, EnumSet.of(DAMAGED, WRONG_ITEM, CHANGED_MIND, SIZE_ISSUE));

    final int windowDays;
    final Set<Reason> reasons;

    /** Clothing and footwear: a customer's-choice return needs the tags attached. */
    boolean needsTags() {
        return this == CLOTHING || this == FOOTWEAR;
    }

    Category(int windowDays, Set<Reason> reasons) {
        this.windowDays = windowDays;
        this.reasons = reasons;

package com.kartwala.refunds;

import java.time.LocalDate;
import java.util.ArrayList;
import java.util.List;

/**
 * The refund rules as one pure function: no Spring, no clock, no database. Everything it needs is a parameter, so a
 * table of cases can test every category and reason in milliseconds. Returns every reason a return is refused.
 */
final class RefundRules {

    /** Demo rule: a return the customer chose (changed mind, size) pays ₹49 for the pickup. */
    static final long PICKUP_FEE_PAISE = 4_900;

    /** Demo rule: festive deliveries of clothing and books can come back until 30 November. */
    static final LocalDate FESTIVE_FROM = LocalDate.of(2026, 10, 15);
    static final LocalDate FESTIVE_TO = LocalDate.of(2026, 11, 15);
    static final LocalDate FESTIVE_LAST_DAY = LocalDate.of(2026, 11, 30);

    record Decision(boolean eligible, List<String> reasons, long refundPaise, LocalDate lastDayToReturn) {
    }

    private RefundRules() {
    }

    static Decision check(Order order, Reason reason, Boolean tagsAttached, Boolean sealIntact, LocalDate today) {
        if (order.deliveredOn() == null) {
            return new Decision(false, List.of("NOT_DELIVERED"), 0, null);   // nothing to return yet: cancel instead
        }
        Category category = order.category();
        LocalDate lastDay = lastDay(category, order.deliveredOn());
        List<String> refused = new ArrayList<>();
        if (today.isAfter(lastDay)) {
            refused.add("WINDOW_CLOSED");
        }
        if (!category.reasons.contains(reason)) {
            refused.add("REASON_NOT_ACCEPTED");
        }
        if (category == Category.CLOTHING && order.hygieneItem() && reason != Reason.DAMAGED && reason != Reason.WRONG_ITEM) {
            refused.add("HYGIENE_ITEM");
        }
        if (category.needsTags() && !tagsAttached && reason.customersChoice) {
            refused.add("TAGS_REMOVED");
        }
        if (category == Category.ELECTRONICS && !sealIntact && reason != Reason.DAMAGED) {
            refused.add("SEAL_BROKEN");
        }
        if (!refused.isEmpty()) {
            return new Decision(false, List.copyOf(refused), 0, lastDay);
        }
        long fee = reason.customersChoice ? PICKUP_FEE_PAISE : 0;
        return new Decision(true, List.of(), Math.max(0, order.pricePaise() - fee), lastDay);
    }

    static LocalDate lastDay(Category category, LocalDate deliveredOn) {
        LocalDate normal = deliveredOn.plusDays(category.windowDays);
        boolean festive = (category == Category.CLOTHING || category == Category.BOOKS)
                && !deliveredOn.isBefore(FESTIVE_FROM) && !deliveredOn.isAfter(FESTIVE_TO);
        return festive && FESTIVE_LAST_DAY.isAfter(normal) ? FESTIVE_LAST_DAY : normal;
    }
}

challenge/solution/RefundService.java

package com.kartwala.refunds;

import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.stereotype.Service;
import org.springframework.web.ErrorResponseException;

import java.time.Clock;
import java.time.LocalDate;
import java.time.ZoneId;
import java.util.Locale;

/** Looks up the order, asks the rules, records the decision. The only place that knows what "today" is. */
@Service
class RefundService {

    static final ZoneId INDIA = ZoneId.of("Asia/Kolkata");

    private final OrderLookup orders;
    private final EligibilityAudit audit;
    private final Clock clock;

    RefundService(OrderLookup orders, EligibilityAudit audit, Clock clock) {
        this.orders = orders;
        this.audit = audit;
        this.clock = clock;
    }

    /** Return windows are counted in the customer's calendar: at 01:30 in India it is already tomorrow. */
    static LocalDate today(Clock clock) {
        return LocalDate.now(clock.withZone(INDIA));
    }

    RefundRules.Decision check(String rawOrderId, Reason reason, Boolean tagsAttached, Boolean sealIntact) {
        String orderId = rawOrderId.toUpperCase(Locale.ROOT);
        Order order = orders.find(orderId).orElseThrow(() -> problem(HttpStatus.NOT_FOUND, "Order not found", "No order " + orderId + "."));
        if (order.category().needsTags() && tagsAttached == null) {
            throw problem(HttpStatus.BAD_REQUEST, "Missing answer",
                    "tagsAttached is required for " + order.category().name().toLowerCase(Locale.ROOT) + ".");
        }
        if (order.category() == Category.ELECTRONICS && sealIntact == null) {
            throw problem(HttpStatus.BAD_REQUEST, "Missing answer", "sealIntact is required for electronics.");
        }
        RefundRules.Decision decision = RefundRules.check(order, reason, tagsAttached, sealIntact, today(clock));
        audit.record(orderId, reason, decision);
        return decision;
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setTitle(title);
        return new ErrorResponseException(status, p, null);
    }
}

Implementation approach

  1. Write the trap test: the old switch passes its own test and refuses clothing.
  2. Move each category's window and reasons onto the category.

A Foundations station: the considerations to know, no runbook.

Time zones
Servers usually run in UTC. Windows promised to customers are in their calendar; a refusal at 1 a.m. that should have been an approval is a support ticket.
Audit
Recording every decision with its reasons answers "why was I refused?" weeks later, and shows which rule refuses most.
Consumer law
Real return policies must respect consumer protection rules (in India, the Consumer Protection (E-Commerce) Rules, 2020); the windows here are demo values.
Test speed
The rule table runs in milliseconds, so it runs on every build. Slow tests get skipped; fast tests get run.

Interview takeaways

What is a parameterized test, and when do you use one?

One test method run for each row of inputs and expected outputs (@CsvSource, @MethodSource, @EnumSource). Use it when the same rule must hold across many cases, such as every category.

Stub or verify?

Stub queries: you care what they return. Verify commands: you care that they happened. Verifying queries couples the test to how the code works, not what it does.

How do you test code that depends on the current time?

Inject a java.time.Clock and call LocalDate.now(clock). In tests use Clock.fixed. Never call LocalDate.now() with no argument in logic.

What makes code testable?

Separating decisions (pure functions) from effects (database, clock, network). The decisions are tested with many fast cases; the effects with a few.

What does Mockito's strict stubbing catch?

A stub the code never used, often a sign the test no longer tests what it claims, or a wrong argument.
