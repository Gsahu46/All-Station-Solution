Level 1, about 5 minutes. Plain language: no code.

The problem in real life

  1. Leave balances ignore holidays

    Employees in Bengaluru lose a day of leave for Kannada Rajyotsava, because Teamdesk does not know it is a holiday.

  2. The first fix calls the provider

    It works in the demo. Then the provider has a slow morning: every leave request waits, threads pile up, and Teamdesk stops answering anyone. When the provider returns 500, Teamdesk returns 500 too.

  3. The fix

    Call the provider with a time limit, and translate each kind of failure into an honest answer of our own: too slow, failed, or no list. Never pass their error text on.

Every call to someone else's service needs a time limit and a plan for each way it can fail.

What are we building?

GET /holidays?year=2026&state=KA asks the holiday provider for a state's holidays and returns them sorted, in our own shape. When the provider is slow or broken, it says so with 504 or 502, quickly.

An everyday analogy

A shopkeeper phones the wholesaler for a price. If nobody answers in a minute, she tells the customer "the wholesaler is not answering, come back later" instead of standing at the phone all day while the queue grows.

How it works in 4 steps

  1. Check the request first: a bad year or state is 400, and the provider is never called.
  2. Call the provider through an interface client, with a 1 s connect and a 2 s read limit.
  3. Translate failures: their 404 is ours; their 5xx, bad key or garbage is 502; their slowness is 504.
  4. Answer in our shape: only the fields we use, sorted by date.
Check yourself: the provider says 401 because our API key expired. Should our client get 401?

No. 401 tells our client they must sign in again, which will not help. The fault is between us and the provider: 502, and an alert for us.

What this station is not

  • No real holiday provider. A simulated one, with a few fixed-date holidays.
  • No retries or circuit breaker. Discussed in Design; a later station builds them.
  • No leave calculation. Only the holiday list.

Business problem

Teamdesk (a fictional HR app) must count public holidays when it computes leave. Holidays come from a provider's API. The first integration had no timeout and no error handling: one slow morning at the provider took Teamdesk down with it, and every provider error reached users as a 500.

Acceptance criteria

  1. Given 2026 and KA, then the provider is asked for year=2026&region=KA and the holidays come back sorted by date, without the provider's extra fields.
  2. Given the provider takes longer than the read limit, then 504, well before the provider answers.
  3. Given the provider answers 500, 401, unreadable data, or hangs up, then 502, and none of its error text in our body.
  4. Given the provider has no list for the state, then 404.
  5. Given an unknown state, a year outside 2000 to 2100, or no year, then 400, and the provider is not called.

Requirements

  • Connect limit 1 s, read limit 2 s, both in configuration.
  • States are normalised with Locale.ROOT; the demo list is KA, MH, DL, TN.
  • The provider's error bodies are logged, never returned.
  • Only the fields we use are mapped; anything else the provider adds is ignored.

Learning objectives

  • Call an HTTP API with RestClient and an @HttpExchange interface.
  • Map a partner's JSON to records.
  • Set timeouts, and translate 4xx, 5xx and timeouts into honest answers.
  • Test against a stub HTTP server that can be slow or broken on demand.

The trap

Plausible but wrong

No timeout and no handling of the partner's 5xx, so our API hangs or 500s.

RestClient.create(url) works in every demo. The first test shows it waiting the full 2 seconds a slow provider takes, and it would wait far longer. The second shows the provider's 500 escaping as an exception, which our API turns into its own 500. The third shows the real endpoint answering 504 within its limit and 502 for the failure. While building, removing the read timeout turned 1 test red, removing the failure handling turned 4 red, and passing the provider's message through turned 2 red.

package com.teamdesk.holidays;

import org.junit.jupiter.api.Test;
import org.springframework.web.client.HttpServerErrorException;
import org.springframework.web.client.RestClient;

import java.time.Duration;
import java.time.Instant;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

/** The first test written for this station: it reproduces the bugs before the fix. */
class SlowProviderTrapTest extends ApiTest {

    /** The "before" call: a RestClient with no timeout and no error handling. Kept only in tests. */
    static String oldCall() {
        return RestClient.create(STUB.baseUrl()).get().uri("/v1/holidays?year=2026&region=KA").retrieve().body(String.class);
    }

    @Test
    void theOldCallWaitsAsLongAsTheProviderLikes() {
        STUB.behaviour = StubProvider.Behaviour.SLOW;
        Instant start = Instant.now();
        oldCall();
        assertThat(Duration.between(start, Instant.now())).isGreaterThanOrEqualTo(Duration.ofMillis(1_900));
        // every request thread stuck like this is one fewer for everyone else
    }

    @Test
    void theOldCallTurnsTheProvidersFailureIntoOurs() {
        STUB.behaviour = StubProvider.Behaviour.FAIL;
        assertThatThrownBy(SlowProviderTrapTest::oldCall)
                .isInstanceOf(HttpServerErrorException.InternalServerError.class);   // uncaught: our API answers 500
    }

    @Test
    void theRealEndpointGivesUpInTimeAndSaysWhoFailed() throws Exception {
        STUB.behaviour = StubProvider.Behaviour.SLOW;
        Instant start = Instant.now();
        holidays("2030", "KA").andExpect(status().isGatewayTimeout())   // years no test fetches successfully: nothing cached
                .andExpect(jsonPath("$.title").value("Holiday provider too slow"));
        assertThat(Duration.between(start, Instant.now())).isLessThan(Duration.ofMillis(1_500));

        STUB.behaviour = StubProvider.Behaviour.FAIL;
        holidays("2031", "KA").andExpect(status().isBadGateway())
                .andExpect(jsonPath("$.title").value("Holiday provider failed"));
    }
}

package com.teamdesk.holidays;

import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.client.HttpClientErrorException;
import org.springframework.web.client.ResourceAccessException;
import org.springframework.web.client.RestClientException;

import java.net.SocketTimeoutException;
import java.net.http.HttpTimeoutException;
import java.time.LocalDate;
import java.util.Comparator;
import java.util.List;
import java.util.Locale;
import java.util.Set;

@RestController
class HolidayController {

    private static final Logger log = LoggerFactory.getLogger(HolidayController.class);

    /** States Teamdesk has offices in (a demo list). */
    static final Set<String> STATES = Set.of("KA", "MH", "DL", "TN");

    record Holiday(LocalDate date, String name, String type) {
    }

    record Holidays(int year, String state, List<Holiday> holidays) {
    }

    private final HolidayProviderClient provider;

    HolidayController(HolidayProviderClient provider) {
        this.provider = provider;
    }

    @GetMapping("/holidays")
    Holidays holidays(@RequestParam @Min(2000) @Max(2100) int year, @RequestParam String state) {
        String region = state.toUpperCase(Locale.ROOT);
        if (!STATES.contains(region)) {
            throw problem(HttpStatus.BAD_REQUEST, "Unknown state", "state must be one of " + String.join(", ", STATES.stream().sorted().toList()) + ".");
        }
        HolidayProviderClient.ProviderResponse answer = call(year, region);
        return new Holidays(year, region, answer.holidays().stream()
                .map(h -> new Holiday(h.date(), h.name(), h.type()))
                .sorted(Comparator.comparing(Holiday::date))
                .toList());
    }

    /**
     * Every way the provider can fail, translated into our own answer. The provider's error body is logged, never
     * passed on: it may name internal hosts or keys, and our clients cannot act on it anyway.
     */
    private HolidayProviderClient.ProviderResponse call(int year, String region) {
        try {
            HolidayProviderClient.ProviderResponse answer = provider.holidays(year, region);
            if (answer == null || answer.holidays() == null) {
                throw new RestClientException("empty answer");
            }
            return answer;
        } catch (HttpClientErrorException.NotFound e) {
            throw problem(HttpStatus.NOT_FOUND, "No holiday list", "The provider has no holiday list for " + region + " in " + year + ".");
        } catch (ResourceAccessException e) {
            boolean timedOut = e.getCause() instanceof HttpTimeoutException || e.getCause() instanceof SocketTimeoutException;
            log.warn("Holiday provider unreachable ({}): {}", timedOut ? "timeout" : "connection", e.getMessage());
            throw timedOut
                    ? problem(HttpStatus.GATEWAY_TIMEOUT, "Holiday provider too slow", "The holiday provider did not answer in time. Try again shortly.")
                    : problem(HttpStatus.BAD_GATEWAY, "Holiday provider unreachable", "The holiday provider could not be reached. Try again shortly.");
        } catch (RestClientException e) {   // its 5xx, any other 4xx (our key or request is wrong), or a body we cannot read
            log.warn("Holiday provider failed: {}", e.getMessage());
            throw problem(HttpStatus.BAD_GATEWAY, "Holiday provider failed", "The holiday provider failed to answer. Try again shortly.");
        }
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setTitle(title);
        return new ErrorResponseException(status, p, null);
    }
}

package com.teamdesk.holidays;

import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.service.annotation.GetExchange;
import org.springframework.web.service.annotation.HttpExchange;

import java.time.LocalDate;
import java.util.List;

/**
 * The holiday provider's API, declared as an interface: Spring writes the HTTP call. Only the fields we use are
 * mapped; the provider's other fields are ignored (Jackson 3's default).
 */
@HttpExchange("/v1/holidays")
interface HolidayProviderClient {

    record ProviderHoliday(LocalDate date, String name, String type) {
    }

    record ProviderResponse(String region, int year, List<ProviderHoliday> holidays) {
    }

    @GetExchange
    ProviderResponse holidays(@RequestParam int year, @RequestParam String region);
}

package com.teamdesk.holidays;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.client.JdkClientHttpRequestFactory;
import org.springframework.web.client.RestClient;
import org.springframework.web.client.support.RestClientAdapter;
import org.springframework.web.service.invoker.HttpServiceProxyFactory;

import java.net.http.HttpClient;
import java.time.Duration;

/**
 * Builds the provider client with time limits. Without them a slow provider holds our request thread for as long
 * as it likes, and enough slow calls take our whole API down with it.
 */
@Configuration
class ProviderClientConfig {

    @Bean
    HolidayProviderClient holidayProviderClient(@Value("${teamdesk.holidays.base-url}") String baseUrl,
                                                @Value("${teamdesk.holidays.connect-timeout}") Duration connectTimeout,
                                                @Value("${teamdesk.holidays.read-timeout}") Duration readTimeout) {
        JdkClientHttpRequestFactory requests = new JdkClientHttpRequestFactory(
                HttpClient.newBuilder().connectTimeout(connectTimeout).build());
        requests.setReadTimeout(readTimeout);
        RestClient rest = RestClient.builder().baseUrl(baseUrl).requestFactory(requests).build();
        return HttpServiceProxyFactory.builderFor(RestClientAdapter.create(rest)).build().createClient(HolidayProviderClient.class);
    }
}

package com.teamdesk.holidays;

import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.time.LocalDate;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;

/**
 * A simulated holiday provider, so the app runs without a real one: the app calls this over HTTP like any partner.
 * Demo data: three fixed-date national holidays and one state day, not an official list.
 * Demo switches: year 2098 answers after 3 seconds, year 2099 answers 500. TN has no list (404).
 */
@RestController
@ConditionalOnProperty("teamdesk.demo-provider.enabled")
class DemoProviderController {

    private static final Map<String, String[]> STATE_DAYS = Map.of(
            "KA", new String[]{"11-01", "Kannada Rajyotsava"},
            "MH", new String[]{"05-01", "Maharashtra Day"});

    @GetMapping("/demo-provider/v1/holidays")
    ResponseEntity<?> holidays(@RequestParam int year, @RequestParam String region) throws InterruptedException {
        if (year == 2098) {
            Thread.sleep(3_000);
        }
        if (year == 2099) {
            return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(Map.of("error", "db-holidays-02 connection pool exhausted"));
        }
        if (region.equals("TN")) {
            return ResponseEntity.status(HttpStatus.NOT_FOUND).body(Map.of("error", "no data for region"));
        }
        List<Map<String, Object>> days = new ArrayList<>(List.of(
                day(year, "08-15", "Independence Day", "NATIONAL"),
                day(year, "01-26", "Republic Day", "NATIONAL"),
                day(year, "10-02", "Gandhi Jayanti", "NATIONAL")));
        if (STATE_DAYS.containsKey(region)) {
            days.add(day(year, STATE_DAYS.get(region)[0], STATE_DAYS.get(region)[1], "STATE"));
        }
        return ResponseEntity.ok(Map.of("country", "IN", "region", region, "year", year, "holidays", days, "generatedBy", "demo"));
    }

    private static Map<String, Object> day(int year, String monthDay, String name, String type) {
        return Map.of("date", LocalDate.parse(year + "-" + monthDay), "name", name, "type", type, "observed", true);
    }
}

src/test/java/com/teamdesk/holidays/StubProvider.java

The fake partner: the JDK's own HTTP server on a random port, told per test how to behave.

package com.teamdesk.holidays;

import com.sun.net.httpserver.HttpExchange;
import com.sun.net.httpserver.HttpServer;

import java.io.IOException;
import java.net.InetSocketAddress;
import java.nio.charset.StandardCharsets;
import java.util.concurrent.Executors;
import java.util.concurrent.atomic.AtomicInteger;

/**
 * A stand-in for the holiday provider: a real HTTP server on a random port (the JDK's own, no extra library), told
 * per test how to behave. Our app calls it over real HTTP, so timeouts and status codes are real too.
 */
final class StubProvider {

    enum Behaviour { NORMAL, SLOW, FAIL, NOT_FOUND, BAD_KEY, BAD_JSON, HANG_UP }

    static final String HOLIDAYS = """
            {"country":"IN","region":"KA","year":2026,"apiVersion":"3.2",
             "holidays":[{"date":"2026-11-01","name":"Kannada Rajyotsava","type":"STATE","observed":true},
                         {"date":"2026-01-26","name":"Republic Day","type":"NATIONAL","observed":true}]}""";

    private final HttpServer server;
    volatile Behaviour behaviour = Behaviour.NORMAL;
    volatile String lastQuery;
    volatile String lastApiKey;
    final AtomicInteger calls = new AtomicInteger();

    private StubProvider(HttpServer server) {
        this.server = server;
    }

    static StubProvider start() {
        try {
            HttpServer server = HttpServer.create(new InetSocketAddress("localhost", 0), 0);
            server.setExecutor(Executors.newCachedThreadPool());   // a slow answer must not block the next request
            StubProvider stub = new StubProvider(server);
            server.createContext("/v1/holidays", stub::handle);
            server.start();
            return stub;
        } catch (IOException e) {
            throw new IllegalStateException(e);
        }
    }

    String baseUrl() {
        return "http://localhost:" + server.getAddress().getPort();
    }

    private void handle(HttpExchange ex) throws IOException {
        calls.incrementAndGet();
        lastQuery = ex.getRequestURI().getQuery();
        lastApiKey = ex.getRequestHeaders().getFirst("X-Api-Key");
        switch (behaviour) {
            case NORMAL -> send(ex, 200, HOLIDAYS);
            case SLOW -> {
                sleep(2_000);
                send(ex, 200, HOLIDAYS);
            }
            case FAIL -> send(ex, 500, "{\"error\":\"db-holidays-02.internal:5432 connection pool exhausted\"}");
            case NOT_FOUND -> send(ex, 404, "{\"error\":\"no data for region\"}");
            case BAD_KEY -> send(ex, 401, "{\"error\":\"api key tdk_live_8f2c expired\"}");
            case BAD_JSON -> send(ex, 200, "<html>Service temporarily unavailable</html>");
            case HANG_UP -> ex.close();   // closes the connection without an answer
        }
    }

    private static void send(HttpExchange ex, int status, String body) throws IOException {
        byte[] bytes = body.getBytes(StandardCharsets.UTF_8);
        ex.getResponseHeaders().add("Content-Type", "application/json");
        ex.sendResponseHeaders(status, bytes.length);
        ex.getResponseBody().write(bytes);
        ex.close();
    }

    private static void sleep(long millis) {
        try {
            Thread.sleep(millis);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

package com.teamdesk.holidays;

import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.client.HttpClientErrorException;
import org.springframework.web.client.ResourceAccessException;
import org.springframework.web.client.RestClientException;

import java.net.SocketTimeoutException;
import java.net.http.HttpTimeoutException;
import java.time.LocalDate;
import java.util.Comparator;
import java.util.List;
import java.util.Locale;
import java.util.Map;
import java.util.Set;
import java.util.concurrent.ConcurrentHashMap;

@RestController
class HolidayController {

    private static final Logger log = LoggerFactory.getLogger(HolidayController.class);

    /** States Teamdesk has offices in (a demo list). */
    static final Set<String> STATES = Set.of("KA", "MH", "DL", "TN");

    record Holiday(LocalDate date, String name, String type) {
    }

    /** Challenge 1: source is "provider" for a fresh answer, "cache" for the last good one. */
    record Holidays(int year, String state, List<Holiday> holidays, String source) {
    }

    /** Challenge 1: the last good answer per year and state. A year's holidays rarely change. */
    private final Map<String, List<Holiday>> lastGood = new ConcurrentHashMap<>();

    private final HolidayProviderClient provider;

    HolidayController(HolidayProviderClient provider) {
        this.provider = provider;
    }

    @GetMapping("/holidays")
    Holidays holidays(@RequestParam @Min(2000) @Max(2100) int year, @RequestParam String state) {
        String region = state.toUpperCase(Locale.ROOT);
        if (!STATES.contains(region)) {
            throw problem(HttpStatus.BAD_REQUEST, "Unknown state", "state must be one of " + String.join(", ", STATES.stream().sorted().toList()) + ".");
        }
        String key = year + "/" + region;
        try {
            List<Holiday> fresh = call(year, region).holidays().stream()
                    .map(h -> new Holiday(h.date(), h.name(), h.type()))
                    .sorted(Comparator.comparing(Holiday::date))
                    .toList();
            lastGood.put(key, fresh);
            return new Holidays(year, region, fresh, "provider");
        } catch (ErrorResponseException failure) {
            List<Holiday> cached = lastGood.get(key);
            if (cached == null || failure.getStatusCode().value() == 404) {
                throw failure;
            }
            log.warn("Serving the last good holiday list for {} instead of: {}", key, failure.getBody().getTitle());
            return new Holidays(year, region, cached, "cache");
        }
    }

    /**
     * Every way the provider can fail, translated into our own answer. The provider's error body is logged, never
     * passed on: it may name internal hosts or keys, and our clients cannot act on it anyway.
     */
    private HolidayProviderClient.ProviderResponse call(int year, String region) {
        try {
            HolidayProviderClient.ProviderResponse answer = provider.holidays(year, region);
            if (answer == null || answer.holidays() == null) {
                throw new RestClientException("empty answer");
            }
            return answer;
        } catch (HttpClientErrorException.NotFound e) {
            throw problem(HttpStatus.NOT_FOUND, "No holiday list", "The provider has no holiday list for " + region + " in " + year + ".");
        } catch (ResourceAccessException e) {
            boolean timedOut = e.getCause() instanceof HttpTimeoutException || e.getCause() instanceof SocketTimeoutException;
            log.warn("Holiday provider unreachable ({}): {}", timedOut ? "timeout" : "connection", e.getMessage());
            throw timedOut
                    ? problem(HttpStatus.GATEWAY_TIMEOUT, "Holiday provider too slow", "The holiday provider did not answer in time. Try again shortly.")
                    : problem(HttpStatus.BAD_GATEWAY, "Holiday provider unreachable", "The holiday provider could not be reached. Try again shortly.");
        } catch (RestClientException e) {   // its 5xx, any other 4xx (our key or request is wrong), or a body we cannot read
            log.warn("Holiday provider failed: {}", e.getMessage());
            throw problem(HttpStatus.BAD_GATEWAY, "Holiday provider failed", "The holiday provider failed to answer. Try again shortly.");
        }
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setTitle(title);
        return new ErrorResponseException(status, p, null);
    }
}

package com.teamdesk.holidays;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.client.JdkClientHttpRequestFactory;
import org.springframework.web.client.RestClient;
import org.springframework.web.client.support.RestClientAdapter;
import org.springframework.web.service.invoker.HttpServiceProxyFactory;

import java.net.http.HttpClient;
import java.time.Duration;

/**
 * Builds the provider client with time limits. Without them a slow provider holds our request thread for as long
 * as it likes, and enough slow calls take our whole API down with it.
 */
@Configuration
class ProviderClientConfig {

    @Bean
    HolidayProviderClient holidayProviderClient(@Value("${teamdesk.holidays.base-url}") String baseUrl,
                                                @Value("${teamdesk.holidays.connect-timeout}") Duration connectTimeout,
                                                @Value("${teamdesk.holidays.read-timeout}") Duration readTimeout,
                                                @Value("${teamdesk.holidays.api-key:}") String apiKey) {
        JdkClientHttpRequestFactory requests = new JdkClientHttpRequestFactory(
                HttpClient.newBuilder().connectTimeout(connectTimeout).build());
        requests.setReadTimeout(readTimeout);
        // Challenge 2: the key from configuration (an environment variable in real life), on every call, never logged.
        RestClient rest = RestClient.builder().baseUrl(baseUrl).requestFactory(requests).defaultHeader("X-Api-Key", apiKey).build();
        return HttpServiceProxyFactory.builderFor(RestClientAdapter.create(rest)).build().createClient(HolidayProviderClient.class);
    }
}

Interview takeaways

What happens without a timeout on an HTTP call?

The thread waits as long as the other side likes. Under load, every request thread ends up waiting and the whole service stops answering.

502 or 504?

504 when the upstream service did not answer in time; 502 when it answered badly (5xx, garbage) or could not be reached.

Should a partner's 401 become our 401?

No. It means our credentials with them are wrong, which our client cannot fix. Answer 502 and alert ourselves.

What is @HttpExchange?

A Spring annotation for declaring an HTTP API as a Java interface. HttpServiceProxyFactory turns it into a client over RestClient.

How do you test a partner integration?

Against a stub HTTP server you control: make it slow, failing, or return garbage, and check each answer. Never against the real partner in unit tests.
