The problem in real life

  1. Priya edits her home address

    She is on a weak signal in a lift. She taps Save; the server saves it, but the reply never reaches her phone.

  2. The app tries again

    The old API used POST, which means "add one more". The retry adds a second "home". At checkout she sees two, and later deleting one shows an error because the other was already gone.

  3. The fix

    Name the address in the URL and use methods that are safe to repeat: PUT …/addresses/home sets it, DELETE removes it. Doing either twice leaves the same result.

Phones retry. The question is not whether a request arrives twice, but whether arriving twice does any harm.

What are we building?

A saved-addresses API where each address is named by a label in the URL (home, work). PUT sets a whole address, PATCH changes some fields, DELETE removes it. Repeating any of them is harmless.

An everyday analogy

A row of labelled letterboxes. "Put this letter in box HOME" twice leaves one letter in HOME, because the second replaces the first. "Drop a letter in the post box" twice sends two letters. PUT is the labelled box; POST is the post box.

How it works in 4 steps

  1. The label is in the URL: /customers/42/addresses/home. Every request is about that one address.
  2. PUT stores the whole address under the label: 201 if new, 200 if replaced. Twice: still one address.
  3. PATCH changes only the fields sent; null removes an optional field. Twice: same result.
  4. DELETE makes sure the address is gone: 204 every time, even if it was already gone.
Check yourself: Priya's DELETE succeeds, but the reply is lost. The app sends DELETE again. What should it get?

204 again. The goal "home is not saved" is already true, so the retry succeeds without doing anything. If the second DELETE returned an error, the app would show an error screen for something that worked.

What this station is not

  • No login. The customer id is in the URL; real apps take it from the signed-in user.
  • No database. Addresses live in memory.
  • No protection against two phones editing at once. The last save wins; Practice challenge 1 adds the fix.

Business problem

Tiffino (the food-delivery app from station 002) lets customers save delivery addresses. The API saves every edit with POST /customers/{id}/addresses, which adds a new entry. On flaky mobile networks the app retries, so customers end up with two or three copies of "home", and riders sometimes go to an old one. Deleting a duplicate a second time shows an error screen. Support tickets about "wrong address" are the top complaint in Bengaluru.

Acceptance criteria

  1. Given a new label, when the app PUTs an address, then 201 with Location. When it PUTs the same again, then 200, the same body, and still one address.
  2. Given a saved address, when the app PUTs a different address, then it replaces the whole address: fields left out are gone.
  3. Given a PATCH, then only the fields sent change; null removes an optional field; removing a required field is 400 and changes nothing.
  4. Given a DELETE, then 204, and a second DELETE is 204 too.
  5. Given a POST to an address, then 405 with an Allow header listing GET, PUT, PATCH and DELETE.
  6. Given 10 saved addresses, when an 11th label is PUT, then 409; replacing an existing one still works.

Requirements

  • Labels: 1–20 lower-case letters, digits or hyphens; HOME and home are the same label (Locale.ROOT).
  • Address fields: line1, city, pincode (6 digits, not starting with 0) required; line2, landmark optional.
  • PATCH uses JSON Merge Patch (application/merge-patch+json; plain JSON is accepted too). Only the five fields may be patched.
  • No timestamps or counters in the stored address, so the same request always leaves exactly the same state.
  • Errors are RFC 9457 problems that never repeat input.

Learning objectives

  • Choose between PUT, PATCH and POST, and explain which are idempotent.
  • Design URLs so that a retry targets the same resource.
  • Implement JSON Merge Patch, including null as "remove".
  • Return 204 for DELETE, and 405 with Allow.
  • Write replay tests: the same request twice gives one effect.

Same state, not always the same status. Idempotency (RFC 9110) is about the effect on the server. A repeated PUT answers 200 where the first answered 201, and that is fine: the address is the same. This API also chose 204 for a repeated DELETE; returning 404 (as station 005 did) would also be idempotent, but it turns a successful retry into an error screen.

The trap

Plausible but wrong

Using POST for edits, so a retry on a flaky network creates duplicates.

"Save address" feels like "create", so POST feels natural, and it works on office Wi-Fi. The first test sends the same POST twice, as an app does after a lost reply, to the "before" API: two addresses. The second sends the same PUT twice to the real API: one. Removing Locale.ROOT from the label was tried while building: the Turkish-locale test went red.

Does
Maps GET, PUT, PATCH and DELETE on /customers/{id}/addresses/{label}, normalises the label, and validates patched results.

package com.tiffino.addresses;

import jakarta.validation.ConstraintViolation;
import jakarta.validation.Valid;
import jakarta.validation.Validator;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.http.ResponseEntity;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PatchMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import tools.jackson.databind.JsonNode;

import java.net.URI;
import java.util.Locale;
import java.util.Map;
import java.util.TreeMap;
import java.util.regex.Pattern;

/**
 * The URL names the address: /customers/42/addresses/home. So every method is about one known resource:
 * PUT sets it, PATCH changes part of it, DELETE removes it, GET reads it. No POST: POST means "add one more",
 * which is exactly what a retry must not do. Spring answers POST here with 405 and an Allow header.
 */
@RestController
@RequestMapping("/customers/{customerId}/addresses")
class AddressController {

    private static final Pattern LABEL = Pattern.compile("[a-z0-9-]{1,20}");
    private final AddressBook book;
    private final Validator validator;

    AddressController(AddressBook book, Validator validator) {
        this.book = book;
        this.validator = validator;
    }

    @GetMapping
    Map<String, Address> all(@PathVariable long customerId) {
        requireCustomer(customerId);
        return book.all(customerId);
    }

    @GetMapping("/{label}")
    Address get(@PathVariable long customerId, @PathVariable String label) {
        requireCustomer(customerId);
        return book.get(customerId, normalise(label)).orElseThrow(AddressController::notFound);
    }

    /** Create or replace the whole address. The same PUT twice leaves the same single address: 201 the first time, then 200. */
    @PutMapping("/{label}")
    ResponseEntity<Address> put(@PathVariable long customerId, @PathVariable String label, @Valid @RequestBody Address address) {
        requireCustomer(customerId);
        String key = normalise(label);
        return switch (book.put(customerId, key, address)) {
            case CREATED -> ResponseEntity.created(URI.create("/customers/" + customerId + "/addresses/" + key)).body(address);
            case REPLACED -> ResponseEntity.ok(address);
            case FULL -> throw problem(HttpStatus.CONFLICT, "Address book full",
                    "A customer can save at most " + AddressBook.MAX_ADDRESSES + " addresses.");
        };
    }

    /** Change only the fields sent (JSON Merge Patch). The address must already exist. */
    @PatchMapping(value = "/{label}", consumes = {"application/merge-patch+json", "application/json"})
    Address patch(@PathVariable long customerId, @PathVariable String label, @RequestBody JsonNode patch) {
        requireCustomer(customerId);
        String key = normalise(label);
        synchronized (book) { // read, merge and save as one step, or a PATCH arriving in between is overwritten
            Address current = book.get(customerId, key).orElseThrow(AddressController::notFound);
            Address patched;
            try {
                patched = MergePatch.apply(current, patch);
            } catch (IllegalArgumentException e) {
                throw problem(HttpStatus.BAD_REQUEST, "Invalid patch", e.getMessage());
            }
            var violations = validator.validate(patched);
            if (!violations.isEmpty()) {
                Map<String, String> errors = new TreeMap<>();
                for (ConstraintViolation<Address> v : violations) {
                    errors.putIfAbsent(v.getPropertyPath().toString(), v.getMessage());
                }
                ErrorResponseException ex = problem(HttpStatus.BAD_REQUEST, "Invalid patch", "The patched address would be invalid.");
                ex.getBody().setProperty("errors", errors);
                throw ex;
            }
            book.put(customerId, key, patched);
            return patched;
        }
    }

    /** 204 whether or not it was there: "make sure it is gone" can be retried safely and always gives the same answer. */
    @DeleteMapping("/{label}")
    ResponseEntity<Void> delete(@PathVariable long customerId, @PathVariable String label) {
        requireCustomer(customerId);
        book.delete(customerId, normalise(label));
        return ResponseEntity.noContent().build();
    }

    /** "Home", "HOME" and " home" name the same address. Locale.ROOT so a Turkish server keeps "I" as "i". */
    private static String normalise(String label) {
        String l = label.strip().toLowerCase(Locale.ROOT);
        if (!LABEL.matcher(l).matches()) {
            throw problem(HttpStatus.BAD_REQUEST, "Invalid label", "Labels are 1-20 letters, digits or hyphens, like home or work-2.");
        }
        return l;
    }

    private void requireCustomer(long customerId) {
        if (!book.customerExists(customerId)) {
            throw problem(HttpStatus.NOT_FOUND, "Customer not found", "No customer has the id " + customerId + ".");
        }
    }

    private static ErrorResponseException notFound() {
        return problem(HttpStatus.NOT_FOUND, "Address not found", "No saved address has this label.");
    }

    private static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail body = ProblemDetail.forStatusAndDetail(status, detail);
        body.setTitle(title);
        return new ErrorResponseException(status, body, null);
    }
}

src/main/java/com/tiffino/addresses/MergePatch.java

Does
Applies a JSON Merge Patch to an address: present replaces, null removes, missing stays.
Why
One small, testable rule for partial updates.
Without it
Clients would have to send the whole address to change one field, and two phones would overwrite each other's untouched fields.
  • Error messages list the allowed fields instead of repeating the one sent.
package com.tiffino.addresses;

import tools.jackson.databind.JsonNode;

import java.util.HashMap;
import java.util.Map;
import java.util.Set;

/**
 * JSON Merge Patch (RFC 7396) for an address: a field that is present replaces the old value, a field set to
 * null removes it, a field left out is unchanged. Applying the same patch twice gives the same address,
 * so this PATCH is idempotent. (A patch like {"addToTip": 10} would not be.)
 */
final class MergePatch {

    static final Set<String> FIELDS = Set.of("line1", "line2", "landmark", "city", "pincode");

    private MergePatch() {
    }

    /** Returns the patched address, or throws IllegalArgumentException naming an unknown field or a non-text value. */
    static Address apply(Address current, JsonNode patch) {
        if (!patch.isObject()) {
            throw new IllegalArgumentException("The patch must be a JSON object.");
        }
        Map<String, String> v = new HashMap<>();
        v.put("line1", current.line1());
        v.put("line2", current.line2());
        v.put("landmark", current.landmark());
        v.put("city", current.city());
        v.put("pincode", current.pincode());
        for (Map.Entry<String, JsonNode> field : patch.properties()) {
            String name = field.getKey();
            JsonNode value = field.getValue();
            if (!FIELDS.contains(name)) {
                // The message names the allowed fields, never the one that was sent (no echo of client input).
                throw new IllegalArgumentException("Only line1, line2, landmark, city and pincode can be patched.");
            }
            if (!value.isNull() && !value.isString()) {
                throw new IllegalArgumentException("Every patched field must be text or null.");
            }
            v.put(name, value.isNull() ? null : value.asString());
        }
        return new Address(v.get("line1"), v.get("line2"), v.get("landmark"), v.get("city"), v.get("pincode"));
    }
}

import java.util.Set;

/**
 * Each customer's addresses, keyed by label. A map, not a list: putting "home" again replaces "home",
 * so a repeated request cannot create a second one. In memory; synchronized so two requests do not interleave.
 */
@Component
class AddressBook {

    static final int MAX_ADDRESSES = 10;
    private final Set<Long> customers = Set.of(42L, 43L);
    private final Map<Long, Map<String, Address>> books = new LinkedHashMap<>();

    boolean customerExists(long customerId) {
        return customers.contains(customerId);
    }

    synchronized Optional<Address> get(long customerId, String label) {
        return Optional.ofNullable(book(customerId).get(label));
    }

    synchronized Map<String, Address> all(long customerId) {
        return Map.copyOf(book(customerId));
    }

    /** What a PUT did. The controller turns it into 201, 200 or 409. */
    enum PutResult { CREATED, REPLACED, FULL }

    synchronized PutResult put(long customerId, String label, Address address) {
        Map<String, Address> book = book(customerId);
        if (!book.containsKey(label) && book.size() >= MAX_ADDRESSES) {
            return PutResult.FULL;
        }
        return book.put(label, address) == null ? PutResult.CREATED : PutResult.REPLACED;
    }

    /** Removes the address if it is there. Removing something already gone is not an error. */
    synchronized void delete(long customerId, String label) {
        book(customerId).remove(label);
    }

    /** For tests only. */
    synchronized void clear() {
        books.clear();
    }

    private Map<String, Address> book(long customerId) {
        return books.computeIfAbsent(customerId, id -> new LinkedHashMap<>());
    }
}

package com.tiffino.addresses;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Pattern;

/**
 * A saved address: both the PUT body and the stored value. The label is not in the body: it is the last part
 * of the URL, which names the address. No "updatedAt" or version on purpose: sending the same PUT twice must
 * leave exactly the same state, and a timestamp would differ.
 */
public record Address(
        @NotBlank @Size(max = 100) String line1,
        @Size(max = 100) String line2,
        @Size(max = 60) String landmark,
        @NotBlank @Size(max = 50) String city,
        @NotBlank @Pattern(regexp = "[1-9]\\d{5}", message = "must be a 6-digit PIN code") String pincode) {

    public Address {
        line1 = strip(line1);
        city = strip(city);
        pincode = strip(pincode);
        line2 = optional(line2);
        landmark = optional(landmark);
    }

    private static String strip(String s) {
        return s == null ? null : s.strip();
    }

    /** A blank optional field means "none", stored as null, so "" and a missing field are the same address. */
    private static String optional(String s) {
        return s == null || s.isBlank() ? null : s.strip();
    }

    }

    @GetMapping("/{label}")
    ResponseEntity<Address> get(@PathVariable long customerId, @PathVariable String label) {
        requireCustomer(customerId);
        Address a = book.get(customerId, normalise(label)).orElseThrow(AddressController::notFound);
        return ResponseEntity.ok().eTag(etag(a)).body(a); // challenge 1
    }

    /**
     * Challenge 1: a fingerprint of the address's content. Same content, same ETag, on any server.
     * shortcut: a 32-bit hash can collide; use SHA-256 when a missed conflict would be costly.
     */
    static String etag(Address a) {
        return "\"" + Integer.toHexString(Objects.hash(a.line1(), a.line2(), a.landmark(), a.city(), a.pincode())) + "\"";
    }

    /** Challenge 1: if the client sent If-Match, the address must still be the version it saw. Call inside synchronized (book). */
    private void checkIfMatch(long customerId, String key, String ifMatch) {
        if (ifMatch != null && !book.get(customerId, key).map(AddressController::etag).filter(ifMatch::equals).isPresent()) {
            throw problem(HttpStatus.PRECONDITION_FAILED, "Address changed",
                    "The address changed since you read it. Read it again, then save your change.");
        }
    }

    /** Create or replace the whole address. The same PUT twice leaves the same single address: 201 the first time, then 200. */
    @PutMapping("/{label}")
    ResponseEntity<Address> put(@PathVariable long customerId, @PathVariable String label,
                                @RequestHeader(value = "If-Match", required = false) String ifMatch,
                                @Valid @RequestBody Address address) {
        requireCustomer(customerId);
        String key = normalise(label);
        AddressBook.PutResult result;
        synchronized (book) { // the check and the save are one step: nobody can save in between
            checkIfMatch(customerId, key, ifMatch);
            result = book.put(customerId, key, address);
        }
        return switch (result) {
            case CREATED -> ResponseEntity.created(URI.create("/customers/" + customerId + "/addresses/" + key)).eTag(etag(address)).body(address);
            case REPLACED -> ResponseEntity.ok().eTag(etag(address)).body(address);
            case FULL -> throw problem(HttpStatus.CONFLICT, "Address book full",
                    "A customer can save at most " + AddressBook.MAX_ADDRESSES + " addresses.");
        };
    }

    /** Change only the fields sent (JSON Merge Patch). The address must already exist. */
    @PatchMapping(value = "/{label}", consumes = {"application/merge-patch+json", "application/json"})
    ResponseEntity<Address> patch(@PathVariable long customerId, @PathVariable String label,
                                  @RequestHeader(value = "If-Match", required = false) String ifMatch,
                                  @RequestBody JsonNode patch) {
        requireCustomer(customerId);
        String key = normalise(label);
        synchronized (book) {
            checkIfMatch(customerId, key, ifMatch);
            Address patched = patched(customerId, key, patch);
            book.put(customerId, key, patched);
            return ResponseEntity.ok().eTag(etag(patched)).body(patched);
        }
    }

    private Address patched(long customerId, String key, JsonNode patch) {
        Address current = book.get(customerId, key).orElseThrow(AddressController::notFound);
        Address patched;
        try {
            patched = MergePatch.apply(current, patch);
        } catch (IllegalArgumentException e) {
            throw problem(HttpStatus.BAD_REQUEST, "Invalid patch", e.getMessage());
        }
        var violations = validator.validate(patched);
        if (!violations.isEmpty()) {
            Map<String, String> errors = new TreeMap<>();
            for (ConstraintViolation<Address> v : violations) {
                errors.putIfAbsent(v.getPropertyPath().toString(), v.getMessage());
            }
            ErrorResponseException ex = problem(HttpStatus.BAD_REQUEST, "Invalid patch", "The patched address would be invalid.");
            ex.getBody().setProperty("errors", errors);
            throw ex;
        }
        return patched;
    }

    /** 204 whether or not it was there: "make sure it is gone" can be retried safely and always gives the same answer. */
    @DeleteMapping("/{label}")
    ResponseEntity<Void> delete(@PathVariable long customerId, @PathVariable String label) {
        requireCustomer(customerId);
        book.delete(customerId, normalise(label));
        return ResponseEntity.noContent().build();
    }

    /** "Home", "HOME" and " home" name the same address. Locale.ROOT so a Turkish server keeps "I" as "i". */
    static String normalise(String label) {
        String l = label.strip().toLowerCase(Locale.ROOT);
        if (!LABEL.matcher(l).matches()) {
            throw problem(HttpStatus.BAD_REQUEST, "Invalid label", "Labels are 1-20 letters, digits or hyphens, like home or work-2.");
        }
        return l;
    }

    void requireCustomer(long customerId) {
        if (!book.customerExists(customerId)) {
            throw problem(HttpStatus.NOT_FOUND, "Customer not found", "No customer has the id " + customerId + ".");
        }
    }

    private static ErrorResponseException notFound() {
        return problem(HttpStatus.NOT_FOUND, "Address not found", "No saved address has this label.");
    }

    static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail body = ProblemDetail.forStatusAndDetail(status, detail);
        body.setTitle(title);
        return new ErrorResponseException(status, body, null);
    }
}

package com.tiffino.addresses;

import jakarta.validation.constraints.NotBlank;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

/**
 * Challenge 2: the default address as its own small resource. PUT sets it to a label; sending the same PUT
 * again changes nothing, so a retry is safe. A separate URL keeps "which one is default" out of the address itself.
 */
@RestController
class DefaultAddressController {

    record DefaultAddress(@NotBlank String label) {
    }

    private final AddressBook book;
    private final AddressController addresses;

    DefaultAddressController(AddressBook book, AddressController addresses) {
        this.book = book;
        this.addresses = addresses;
    }

    @PutMapping("/customers/{customerId}/default-address")
    DefaultAddress set(@PathVariable long customerId, @RequestBody DefaultAddress request) {
        addresses.requireCustomer(customerId);
        String label = AddressController.normalise(request.label());
        if (!book.setDefault(customerId, label)) {
            throw AddressController.problem(HttpStatus.CONFLICT, "No such address", "Save an address with this label first.");
        }
        return new DefaultAddress(label);
    }

    @GetMapping("/customers/{customerId}/default-address")
    DefaultAddress get(@PathVariable long customerId) {
        addresses.requireCustomer(customerId);
        return book.defaultLabel(customerId).map(DefaultAddress::new)
                .orElseThrow(() -> AddressController.problem(HttpStatus.NOT_FOUND, "No default address", "No default address is set."));
    }
}

challenge/solution/AddressBook.java

package com.tiffino.addresses;

import org.springframework.stereotype.Component;

import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.Map;
import java.util.Optional;
import java.util.Set;

/**
 * Each customer's addresses, keyed by label. A map, not a list: putting "home" again replaces "home",
 * so a repeated request cannot create a second one. In memory; synchronized so two requests do not interleave.
 */
@Component
class AddressBook {

    static final int MAX_ADDRESSES = 10;
    private final Set<Long> customers = Set.of(42L, 43L);
    private final Map<Long, Map<String, Address>> books = new LinkedHashMap<>();
    /** Challenge 2: customer -> label of the default address. */
    private final Map<Long, String> defaults = new HashMap<>();

    boolean customerExists(long customerId) {
        return customers.contains(customerId);
    }

    synchronized Optional<Address> get(long customerId, String label) {
        return Optional.ofNullable(book(customerId).get(label));
    }

    synchronized Map<String, Address> all(long customerId) {
        return Map.copyOf(book(customerId));
    }

    /** What a PUT did. The controller turns it into 201, 200 or 409. */
    enum PutResult { CREATED, REPLACED, FULL }

    synchronized PutResult put(long customerId, String label, Address address) {
        Map<String, Address> book = book(customerId);
        if (!book.containsKey(label) && book.size() >= MAX_ADDRESSES) {
            return PutResult.FULL;
        }
        return book.put(label, address) == null ? PutResult.CREATED : PutResult.REPLACED;
    }

    /** Removes the address if it is there. Removing something already gone is not an error. */
    synchronized void delete(long customerId, String label) {
        book(customerId).remove(label);
        defaults.remove(customerId, label); // challenge 2: no default pointing at a deleted address
    }

    /** Challenge 2. False if the customer has no address with this label. */
    synchronized boolean setDefault(long customerId, String label) {
        if (!book(customerId).containsKey(label)) {
            return false;
        }
        defaults.put(customerId, label);
        return true;
    }

    synchronized Optional<String> defaultLabel(long customerId) {
        return Optional.ofNullable(defaults.get(customerId));
    }

    /** For tests only. */
    synchronized void clear() {
        books.clear();
        defaults.clear();
    }

    private Map<String, Address> book(long customerId) {
        return books.computeIfAbsent(customerId, id -> new LinkedHashMap<>());
    }
}

Reliability
Idempotent methods let apps, proxies and libraries retry safely. Some HTTP clients and proxies retry idempotent methods automatically but, by default, not POST.
Concurrency
Idempotent does not mean conflict-free: two phones with different edits still overwrite each other. Challenge 1 adds ETag/If-Match.
Security
The customer id in the URL is a demo shortcut; real APIs take it from the login, or anyone can edit anyone's addresses. Addresses are personal data: do not log them.

The rules for an address live in one record; PUT and PATCH both end in the same validation.

Interview takeaways

Which HTTP methods are idempotent?

GET, HEAD, OPTIONS, PUT and DELETE are defined as idempotent by RFC 9110. POST is not. PATCH is not guaranteed: it depends on the patch ("set landmark" is, "add 20 to tip" is not).

PUT or PATCH?

PUT replaces the whole resource with the body, so fields left out are removed. PATCH changes only what the patch describes. Use PUT when the client has the full state, PATCH for small changes.

What does null mean in a JSON Merge Patch?

Remove that field. A field left out of the patch is unchanged. That is why Merge Patch cannot set a field to JSON null: null always means remove.

Should a second DELETE return 204 or 404?

Both are idempotent: the server state is the same. 204 makes retries invisible to users; 404 tells the client it was already gone. Pick one, document it, and test it.

Why is POST on /addresses/home a 405 and not a 404?

The URL exists; the method is not supported on it. 405 with an Allow header tells the client which methods do work.
