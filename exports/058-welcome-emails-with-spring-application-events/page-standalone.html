The problem in real life

  1. Sign-up did everything

    Taskloom's sign-up sent the welcome email, told the CRM and the analytics system, then answered. When the CRM was slow, sign-up was slow.

  2. Events, too early

    The team switched to events, with plain listeners. They run inside publishEvent, before the commit. Sign-ups rolled back later, for a full team invite, had already been welcomed by email.

  3. The fix

    Listeners that run after commit, on other threads; one welcome email per sign-up however often the event arrives; retries, then a dead-letter state; and a name escaped before it goes into HTML.

Side effects belong after the commit, and off the request's path.

What are we building?

POST /signups saves a sign-up (optionally joining a team through an invite) and answers at once. After it commits, two things happen on their own: a welcome email and a CRM record. GET /signups/{id} shows where the welcome email is.

An everyday analogy

A hotel front desk. The receptionist checks you in and hands over the key. Only then does someone else send the welcome note and update the loyalty system. If check-in is cancelled halfway, nobody sends the note; if the loyalty system is slow, you still get your key.

How it works in 4 steps

  1. The service saves the sign-up and publishes SignedUp; nothing happens yet.
  2. It may still fail (a full invite): then everything rolls back, and the event is dropped.
  3. On commit, Spring hands the event to the after-commit listeners, each on its own thread.
  4. The email listener claims the email once, sends it, retries if the provider fails, and gives up to DEAD after three attempts.
Check yourself: the email listener runs after commit. Why must it still guard against duplicates?

Events can arrive twice: a retry by a person, a re-published event, a second instance. Without the claim row, each one sends an email. With it, the database lets exactly one through.

What this station is not

  • No real email or CRM. Both are simulated.
  • No outbox. Events live in memory: a crash between commit and listener loses the email (see Production).
  • No login. Sign-up is the start.

Business problem

Taskloom (a fictional SaaS) welcomed people whose sign-up had failed, and made every sign-up wait for its slowest partner system.

Acceptance criteria

  1. Given Asha signs up, then 201 with welcomeEmail PENDING, then one UTF-8 HTML welcome email, then SENT.
  2. Given Ravi signs up with a full invite, then 409, no sign-up, and no email, ever.
  3. Given the CRM hangs, then the sign-up still answers in under 2 seconds and the email still goes.
  4. Given the same event five times at once, then one email.
  5. Given the provider fails twice, then the third attempt sends it; failing every time, the email is DEAD after 3 attempts, with the error.
  6. Given a name like Zoë <b>& co</b> or one with a line break, then it is text in the body and one line in the subject.
  7. Given a malformed body, 400; a taken email, 409; an unknown invite, 422; an unknown sign-up, 404.

Requirements

  • Side effects run after commit, never for a rolled-back sign-up.
  • Slow partners never slow the sign-up.
  • One welcome email per sign-up, guarded by the database.
  • Bounded retries, then a visible dead-letter state.

Learning objectives

  • Publish and listen to application events.
  • Choose between @EventListener and @TransactionalEventListener.
  • Run listeners asynchronously, and test asynchronous code.
  • Make a side effect idempotent, retried, and dead-lettered; and write safe HTML email.

The trap

Plausible but wrong

Sending email in a plain listener before commit; failed sign-ups still get mail.

The old flow is kept in the tests as OldSignupFlow, with the same steps as today and a plain @EventListener that sends the welcome email. Ravi signs up with a full invite: the exception rolls the sign-up back, there is no account, and the mailbox holds one "Welcome to Taskloom" addressed to him. Through today's API the same request leaves no sign-up and, checked for half a second, no email.

While building, each part was undone once. A synchronous plain listener, the old shape, turned 2 tests red: the trap and the full-invite contract test. An @Async plain listener turned a different one red. It ran on another thread before the commit, when PostgreSQL could not yet see the new sign-up, so its claim failed on sent_emails_signup_fk and a valid sign-up got no email. A CRM listener without @Async turned 1 red (the hanging-CRM test). Without the claim, 2; with one attempt instead of three, 2; without escaping, 1.

package com.taskloom.welcome;

import org.springframework.context.ApplicationEventPublisher;
import org.springframework.context.event.EventListener;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.transaction.annotation.Transactional;

/**
 * The sign-up as it shipped, kept only in tests (registered as beans by the trap test). Same steps as today; the
 * difference is the listener: a plain @EventListener runs at once, inside publishEvent, before the transaction ends.
 */
class OldSignupFlow {

    record OldSignedUp(long signupId, String email, String name) {
    }

    private final JdbcClient jdbc;
    private final ApplicationEventPublisher events;

    OldSignupFlow(JdbcClient jdbc, ApplicationEventPublisher events) {
        this.jdbc = jdbc;
        this.events = events;
    }

    @Transactional
    public void signUp(String email, String name, String invite) {
        long id = jdbc.sql("INSERT INTO signups (email, name) VALUES (?, ?) RETURNING id").params(email, name).query(Long.class).single();
        events.publishEvent(new OldSignedUp(id, email, name));   // the email goes out right here
        if (jdbc.sql("UPDATE invites SET seats_used = seats_used + 1 WHERE code = ? AND seats_used < seats_total").param(invite).update() == 0) {
            throw new IllegalStateException("invite full");      // ...and the sign-up rolls back after it
        }
    }

    static class OldWelcomeListener {

        private final MailGateway mail;

        OldWelcomeListener(MailGateway mail) {
            this.mail = mail;
        }

        @EventListener
        public void send(OldSignedUp e) {
            mail.send(WelcomeEmail.to(e.email(), e.name()));
        }
    }
}

import jakarta.validation.Valid;
import jakarta.validation.constraints.Email;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

import java.net.URI;
import java.util.Locale;

@RestController
class SignupController {

    record NewSignup(@NotBlank @Email @Size(max = 254) String email, @NotBlank @Size(max = 80) String name,
                     @Pattern(regexp = "[A-Za-z0-9-]{4,20}") String inviteCode) {
    }

    private final SignupService signups;

    SignupController(SignupService signups) {
        this.signups = signups;
    }

    /** Answers as soon as the sign-up is committed; the welcome email and the CRM follow on their own. */
    @PostMapping("/signups")
    ResponseEntity<SignupService.Signup> signUp(@Valid @RequestBody NewSignup body) {
        SignupService.Signup s = signups.signUp(body.email().strip().toLowerCase(Locale.ROOT), body.name().strip(),
                body.inviteCode() == null ? null : body.inviteCode().toUpperCase(Locale.ROOT));
        return ResponseEntity.created(URI.create("/signups/" + s.id())).body(s);
    }

    /** welcomeEmail: PENDING, SENDING, SENT or DEAD (given up after the last retry). */
    @GetMapping("/signups/{id}")
    SignupService.Signup get(@PathVariable long id) {
        return signups.find(id).orElseThrow(() -> SignupService.problem(HttpStatus.NOT_FOUND, "Sign-up not found", "No sign-up " + id + "."));
    }
}

package com.taskloom.welcome;

import org.springframework.context.ApplicationEventPublisher;
import org.springframework.dao.DuplicateKeyException;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.web.ErrorResponseException;

import java.util.Optional;

/**
 * Sign-up knows nothing about email, the CRM or analytics: it saves the sign-up, says so with an event, and
 * finishes. Whatever listens decides what happens next.
 */
@Service
class SignupService {

    record Signup(long id, String email, String name, String welcomeEmail) {
    }

    private final JdbcClient jdbc;
    private final ApplicationEventPublisher events;

    SignupService(JdbcClient jdbc, ApplicationEventPublisher events) {
        this.jdbc = jdbc;
        this.events = events;
    }

    @Transactional
    Signup signUp(String email, String name, String inviteCode) {
        long id;
        try {
            id = jdbc.sql("INSERT INTO signups (email, name) VALUES (?, ?) RETURNING id").params(email, name).query(Long.class).single();
        } catch (DuplicateKeyException e) {
            throw problem(HttpStatus.CONFLICT, "Already signed up", email + " has already signed up.");
        }
        events.publishEvent(new SignedUp(id, email, name));   // nothing happens yet for after-commit listeners
        if (inviteCode != null) {
            joinTeam(id, inviteCode);   // can still fail, and roll everything back, after the event was published
        }
        return new Signup(id, email, name, "PENDING");
    }

    private void joinTeam(long signupId, String code) {
        int seated = jdbc.sql("UPDATE invites SET seats_used = seats_used + 1 WHERE code = ? AND seats_used < seats_total").param(code).update();
        if (seated == 0) {
            boolean exists = jdbc.sql("SELECT count(*) FROM invites WHERE code = ?").param(code).query(Long.class).single() > 0;
            throw exists ? problem(HttpStatus.CONFLICT, "Invite full", "Invite " + code + " has no seats left.")
                    : problem(HttpStatus.UNPROCESSABLE_CONTENT, "Unknown invite", "No invite " + code + ".");
        }
        jdbc.sql("UPDATE signups SET invite_code = ? WHERE id = ?").params(code, signupId).update();
    }

    Optional<Signup> find(long id) {
        return jdbc.sql("""
                SELECT s.id, s.email, s.name, coalesce(e.status, 'PENDING') AS welcome_email
                FROM signups s LEFT JOIN sent_emails e ON e.signup_id = s.id AND e.kind = 'WELCOME' WHERE s.id = ?""")
                .param(id).query(Signup.class).optional();
    }

    static ErrorResponseException problem(HttpStatus status, String title, String detail) {
        ProblemDetail p = ProblemDetail.forStatusAndDetail(status, detail);
        p.setTitle(title);
        return new ErrorResponseException(status, p, null);
    }
}

Does
The welcome email and the CRM, each @Async and after commit.
Why
Rolled-back sign-ups cause nothing; slow partners slow nothing.
Without it
Mail for sign-ups that do not exist.
  • @TransactionalEventListener(phase = AFTER_COMMIT) holds the event until the commit, and drops it on rollback.

package com.taskloom.welcome;

import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Component;
import org.springframework.transaction.event.TransactionPhase;
import org.springframework.transaction.event.TransactionalEventListener;

/**
 * The two things a sign-up causes. Both run only AFTER the sign-up's transaction commits (a rolled-back sign-up
 * causes nothing), and both on another thread (a slow CRM does not slow the sign-up). Limit: the event lives in
 * memory, so a crash between commit and listener loses it; a transactional outbox closes that gap.
 */
@Component
class Listeners {

    private final WelcomeMailer mailer;
    private final CrmClient crm;

    Listeners(WelcomeMailer mailer, CrmClient crm) {
        this.mailer = mailer;
        this.crm = crm;
    }

    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void sendWelcomeEmail(SignedUp e) {
        mailer.sendOnce(e);
    }

    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void registerInCrm(SignedUp e) {
        crm.register(e.signupId(), e.email(), e.name());
    }
}

package com.taskloom.welcome;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Component;

/**
 * Sends one welcome email per sign-up, even if the event arrives twice: it claims the email in the sent_emails table
 * first. A failing provider is retried with growing waits; after the last attempt the email is marked DEAD (the
 * dead-letter state) for a person to look at, instead of being retried forever or lost.
 */
@Component
class WelcomeMailer {

    private static final Logger log = LoggerFactory.getLogger(WelcomeMailer.class);

    private final JdbcClient jdbc;
    private final MailGateway mail;
    private final int attempts;
    private final long backoffMs;

    WelcomeMailer(JdbcClient jdbc, MailGateway mail, @Value("${taskloom.mail.attempts}") int attempts, @Value("${taskloom.mail.backoff-ms}") long backoffMs) {
        this.jdbc = jdbc;
        this.mail = mail;
        this.attempts = attempts;
        this.backoffMs = backoffMs;
    }

    void sendOnce(SignedUp e) {
        int claimed = jdbc.sql("INSERT INTO sent_emails (signup_id, kind, status) VALUES (?, 'WELCOME', 'SENDING') ON CONFLICT DO NOTHING").param(e.signupId()).update();
        if (claimed == 0) {
            log.info("Welcome email for sign-up {} already claimed: duplicate event ignored", e.signupId());
            return;
        }
        MailGateway.Message message = WelcomeEmail.to(e.email(), e.name());
        for (int attempt = 1; attempt <= attempts; attempt++) {
            try {
                mail.send(message);
                jdbc.sql("UPDATE sent_emails SET status = 'SENT', attempts = ? WHERE signup_id = ? AND kind = 'WELCOME'").params(attempt, e.signupId()).update();
                log.info("Welcome email for sign-up {} sent on attempt {} (simulated: recorded in the mailbox)", e.signupId(), attempt);
                return;
            } catch (RuntimeException failure) {
                String error = String.valueOf(failure.getMessage());
                jdbc.sql("UPDATE sent_emails SET attempts = ?, last_error = ? WHERE signup_id = ? AND kind = 'WELCOME'")
                        .params(attempt, error.length() > 200 ? error.substring(0, 200) : error, e.signupId()).update();
                log.warn("Welcome email for sign-up {} failed, attempt {} of {}: {}", e.signupId(), attempt, attempts, error);
                if (attempt < attempts) {
                    pause(backoffMs * attempt);
                }
            }
        }
        jdbc.sql("UPDATE sent_emails SET status = 'DEAD' WHERE signup_id = ? AND kind = 'WELCOME'").param(e.signupId()).update();
    }

    private static void pause(long ms) {
        try {
            Thread.sleep(ms);
        } catch (InterruptedException interrupted) {
            Thread.currentThread().interrupt();
        }
    }
}

    }

        await().atMost(Duration.ofSeconds(5)).untilAsserted(assertion::run);
    }

    void neverAnyMail() {
        await().during(Duration.ofMillis(500)).atMost(Duration.ofSeconds(2)).until(() -> mailbox.all().isEmpty());
    }

    /** Runs n copies of the task on virtual threads, all released together by one latch. */
    static <T> List<T> together(int n, Callable<T> task) throws Exception {
        CountDownLatch start = new CountDownLatch(1);
        List<Future<T>> futures = new ArrayList<>();
        try (ExecutorService threads = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < n; i++) {
                futures.add(threads.submit(() -> {
                    start.await();
                    return task.call();
                }));
            }
            start.countDown();
        }
        List<T> results = new ArrayList<>();
        for (Future<T> f : futures) {
            results.add(f.get());
        }
        return results;
    }

package com.taskloom.welcome;

import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Component;
import org.springframework.transaction.event.TransactionPhase;
import org.springframework.transaction.event.TransactionalEventListener;

/**
 * The two things a sign-up causes. Both run only AFTER the sign-up's transaction commits (a rolled-back sign-up
 * causes nothing), and both on another thread (a slow CRM does not slow the sign-up). Limit: the event lives in
 * memory, so a crash between commit and listener loses it; a transactional outbox closes that gap.
 */
@Component
class Listeners {

    private final WelcomeMailer mailer;
    private final CrmClient crm;
    private final JdbcClient jdbc;

    Listeners(WelcomeMailer mailer, CrmClient crm, JdbcClient jdbc) {
        this.mailer = mailer;
        this.crm = crm;
        this.jdbc = jdbc;
    }

    /** A new reaction to sign-ups is a new listener: SignupService does not change. */
    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void countForAnalytics(SignedUp e) {
        jdbc.sql("INSERT INTO analytics_events (name, signup_id) VALUES ('signed_up', ?)").param(e.signupId()).update();
    }

    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void sendWelcomeEmail(SignedUp e) {
        mailer.sendOnce(e);
    }

    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void registerInCrm(SignedUp e) {
        crm.register(e.signupId(), e.email(), e.name());
    }
}

package com.taskloom.welcome;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Component;

/**
 * Sends one welcome email per sign-up, even if the event arrives twice: it claims the email in the sent_emails table
 * first. A failing provider is retried with growing waits; after the last attempt the email is marked DEAD (the
 * dead-letter state) for a person to look at, instead of being retried forever or lost.
 */
@Component
class WelcomeMailer {

    private static final Logger log = LoggerFactory.getLogger(WelcomeMailer.class);

    private final JdbcClient jdbc;
    private final MailGateway mail;
    private final int attempts;
    private final long backoffMs;

    WelcomeMailer(JdbcClient jdbc, MailGateway mail, @Value("${taskloom.mail.attempts}") int attempts, @Value("${taskloom.mail.backoff-ms}") long backoffMs) {
        this.jdbc = jdbc;
        this.mail = mail;
        this.attempts = attempts;
        this.backoffMs = backoffMs;
    }

    void sendOnce(SignedUp e) {
        int claimed = jdbc.sql("INSERT INTO sent_emails (signup_id, kind, status) VALUES (?, 'WELCOME', 'SENDING') ON CONFLICT DO NOTHING").param(e.signupId()).update();
        if (claimed == 0) {
            log.info("Welcome email for sign-up {} already claimed: duplicate event ignored", e.signupId());
            return;
        }
        deliver(e);
    }

    /** A person's decision to try a dead-lettered email again: back to SENDING, then the same retries. */
    boolean retryDead(SignedUp e) {
        int revived = jdbc.sql("UPDATE sent_emails SET status = 'SENDING', attempts = 0 WHERE signup_id = ? AND kind = 'WELCOME' AND status = 'DEAD'")
                .param(e.signupId()).update();
        if (revived == 0) {
            return false;
        }
        deliver(e);
        return true;
    }

    private void deliver(SignedUp e) {
        MailGateway.Message message = WelcomeEmail.to(e.email(), e.name());
        for (int attempt = 1; attempt <= attempts; attempt++) {
            try {
                mail.send(message);
                jdbc.sql("UPDATE sent_emails SET status = 'SENT', attempts = ? WHERE signup_id = ? AND kind = 'WELCOME'").params(attempt, e.signupId()).update();
                log.info("Welcome email for sign-up {} sent on attempt {} (simulated: recorded in the mailbox)", e.signupId(), attempt);
                return;
            } catch (RuntimeException failure) {
                String error = String.valueOf(failure.getMessage());
                jdbc.sql("UPDATE sent_emails SET attempts = ?, last_error = ? WHERE signup_id = ? AND kind = 'WELCOME'")
                        .params(attempt, error.length() > 200 ? error.substring(0, 200) : error, e.signupId()).update();
                log.warn("Welcome email for sign-up {} failed, attempt {} of {}: {}", e.signupId(), attempt, attempts, error);
                if (attempt < attempts) {
                    pause(backoffMs * attempt);
                }
            }
        }
        jdbc.sql("UPDATE sent_emails SET status = 'DEAD' WHERE signup_id = ? AND kind = 'WELCOME'").param(e.signupId()).update();
    }

    private static void pause(long ms) {
        try {
            Thread.sleep(ms);
        } catch (InterruptedException interrupted) {
            Thread.currentThread().interrupt();
        }
    }
}

        return ResponseEntity.created(URI.create("/signups/" + s.id())).body(s);
    }

    @PostMapping("/signups/{id}/welcome-email/retry")

        if (!mailer.retryDead(new SignedUp(s.id(), s.email(), s.name()))) {
            throw SignupService.problem(HttpStatus.CONFLICT, "Not dead-lettered", "The welcome email of sign-up " + id + " is " + s.welcomeEmail() + ".");
        }
        return signups.find(id).orElseThrow();
    }

    /** welcomeEmail: PENDING, SENDING, SENT or DEAD (given up after the last retry). */
    @GetMapping("/signups/{id}")
    SignupService.Signup get(@PathVariable long id) {
        return signups.find(id).orElseThrow(() -> SignupService.problem(HttpStatus.NOT_FOUND, "Sign-up not found", "No sign-up " + id + "."));
    }

Interview takeaways

@EventListener vs @TransactionalEventListener?

@EventListener runs immediately, inside publishEvent, in the publisher's transaction. @TransactionalEventListener waits for a transaction phase, by default AFTER_COMMIT, and is skipped if the transaction rolls back.

Why make the listener @Async?

So its work, and any slowness or failure in it, does not delay the request. The trade-off: errors no longer reach the caller, so they must be recorded somewhere.

How do you stop duplicate emails?

Claim the email in the database before sending: a unique key on (sign-up, kind) and INSERT ... ON CONFLICT DO NOTHING. Only the caller that inserted the row sends.

What is a dead letter?

A message that failed every allowed attempt, set aside with its error for a person, instead of being retried forever or dropped.

Why escape a name in an email?

It is user input placed into HTML. Unescaped, "<script>" or "<a href>" becomes markup in the email; a line break in a subject header can add headers.
