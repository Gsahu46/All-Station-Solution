Level 1, about 5 minutes. Plain language: no code.

The problem in real life

  1. Meera uploads a year of transactions

    5,000 lines from her bank's export. One line, 4,812, has a date written 31.03.2026.

  2. The app says "Something went wrong"

    The parser stopped at that line and threw an exception nobody caught. Nothing was imported, and nothing says which line to fix.

  3. The fix

    Read every line. Keep the good ones, and list each bad one with its line number, the field and what was wrong, so Meera fixes one line, once.

An error the customer can act on names the line, the field and the value.

What are we building?

POST /statements/parse takes a statement CSV and returns the transactions it could read, plus a list of every line it could not read and why.

An everyday analogy

A teacher marking 50 answer sheets does not stop at the first mistake and hand everything back with "wrong". She marks every sheet and writes the question number next to each mistake.

How it works in 4 steps

  1. Check the header: the first line must name the five columns.
  2. Read each line: split the fields, parse the date strictly, turn amounts into paise.
  3. Catch per line: a bad line becomes an error with its line number; the loop carries on.
  4. Report: COMPLETE, PARTIAL or REJECTED, with the transactions and the errors.
Check yourself: why is quietly reading 31/02/2026 as 28/02/2026 worse than an error?

The statement now contains a transaction on a day it did not happen, and nobody knows. An error is annoying once; a silent change is wrong forever.

What this station is not

  • No storage. The result is returned, not saved.
  • Not a full CSV library. Line breaks inside quoted fields are not supported (a demo rule).
  • One bank format. Challenge 2 accepts other banks' column names.

Business problem

Tijori (a fictional fintech app) imports bank statements for budgeting. Its parser stops at the first bad line and the error reaches the customer as "Something went wrong". Support cannot tell which line was wrong either, so customers retry the same file, again and again.

Acceptance criteria

  1. Given 5,000 lines with a bad date on line 4,812, then 4,999 transactions, status PARTIAL, and one error naming line 4,812, the field date and the value.
  2. Given 31/02/2026, 29/02/2025 or 01/13/2026, then an error, never an adjusted date.
  3. Given "1,23,456.50", then 12,345,650 paise; "12.345", "-5" or "ten" is an error.
  4. Given quoted fields with commas or "", then they are read whole.
  5. Given no header, or more than 10,000 lines, then 422; an empty body 400; JSON 415.
  6. Given 150 bad lines, then errorCount 150 and the first 100 listed.

Requirements

  • Line numbers are as a spreadsheet shows them: the header is line 1.
  • Dates: dd/MM/yyyy, dd-MM-yyyy or yyyy-MM-dd, strictly.
  • Exactly one of debit and credit has an amount. Amounts are whole paise.
  • Error values are cut to 40 characters; at most 100 errors are listed (demo rules).

Learning objectives

  • Parse and trim text fields, including quoted CSV fields.
  • Parse dates with several formats, strictly, and know why STRICT needs uuuu.
  • Explain checked versus unchecked exceptions, and use a checked one on purpose.
  • Collect per-line errors instead of failing on the first.

The trap

Plausible but wrong

Failing the whole file on one bad line, with no line number in the error.

The first test shows the old loop throwing at line 4,812 with a message that does not mention the line. It is an unchecked exception, so nothing forced anyone to handle it. The second shows the default date formatter quietly turning 31 February into 28 February. The third shows the fixed parser reading 4,999 lines and naming line 4,812. While building, stopping at the first error turned 3 tests red, dropping STRICT turned 2 red, and counting lines from 1 instead of 2 turned 3 red.

package com.tijori.statementimport;

import org.junit.jupiter.api.Test;

import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

/** The first test written for this station: it reproduces the bugs before the fix. */
class OneBadLineTrapTest extends ApiTest {

    /** A 5,000-line statement whose line 4,812 has a date with the wrong separator. */
    static final String UPLOAD = statement(5_000, 4_812, "31.03.2026,UPI to grocer,10.00,,90000.00");

    /** The "before" parser: the first exception ends everything. Kept only in tests. */
    static int oldParse(String csv) {
        DateTimeFormatter format = DateTimeFormatter.ofPattern("dd/MM/yyyy");
        int read = 0;
        for (String line : csv.lines().skip(1).toList()) {
            LocalDate.parse(line.split(",")[0], format);
            read++;
        }
        return read;
    }

    @Test
    void theOldParserGivesUpAtTheFirstBadLineAndDoesNotSayWhichOne() {
        assertThatThrownBy(() -> oldParse(UPLOAD))
                .isInstanceOf(DateTimeParseException.class)   // unchecked: nothing forced anyone to handle it, so it became a 500
                .hasMessageNotContaining("4812")
                .hasMessageNotContaining("4,812");
    }

    @Test
    void theOldDateFormatQuietlyTurnsThirtyFirstFebruaryIntoTheTwentyEighth() {
        // The default SMART resolver "fixes" an impossible date instead of reporting it.
        assertThat(LocalDate.parse("31/02/2026", DateTimeFormatter.ofPattern("dd/MM/yyyy"))).isEqualTo(LocalDate.of(2026, 2, 28));
    }

    @Test
    void theFixedParserReadsEveryOtherLineAndNamesTheBadOne() throws Exception {
        parse(UPLOAD)
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.status").value("PARTIAL"))
                .andExpect(jsonPath("$.linesRead").value(5000))
                .andExpect(jsonPath("$.transactions.length()").value(4999))
                .andExpect(jsonPath("$.errorCount").value(1))
                .andExpect(jsonPath("$.errors[0].line").value(4812))
                .andExpect(jsonPath("$.errors[0].field").value("date"))
                .andExpect(jsonPath("$.errors[0].value").value("31.03.2026"));
    }
}

package com.tijori.statementimport;

import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

@RestController
class StatementController {

    /**
     * Reads a statement CSV and reports every line it could not read, with its line number. Nothing is stored:
     * the app shows the result and the customer fixes the listed lines.
     */
    // shortcut: the whole body is read into memory before the line limit applies; cap upload size at the proxy, or stream lines, for big files
    @PostMapping(path = "/statements/parse", consumes = "text/csv")
    StatementParser.Result parse(@RequestBody String csv) {
        try {
            return StatementParser.parse(csv);
        } catch (StatementParser.FileProblem e) {
            ProblemDetail p = ProblemDetail.forStatusAndDetail(HttpStatus.UNPROCESSABLE_CONTENT, e.getMessage());
            p.setTitle("Statement file cannot be read");
            throw new ErrorResponseException(HttpStatus.UNPROCESSABLE_CONTENT, p, e);
        }
    }
}

src/main/java/com/tijori/statementimport/StatementParser.java

Does
The header check, the per-line loop, strict dates and amounts.
Why
A checked LineException per line: the loop must catch it, so one bad line can never end the file.
Without it
The trap: the first exception ends everything.
  • DATE_FORMATS are tried in order; each is STRICT (ISO_LOCAL_DATE is strict already).
  • File-level problems are an unchecked FileProblem: there is nothing to continue with.
  • lines(), not strip(): a leading blank line must not shift line numbers.
package com.tijori.statementimport;

import java.math.BigDecimal;
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;
import java.time.format.ResolverStyle;
import java.util.ArrayList;
import java.util.List;
import java.util.Locale;

/**
 * Reads the statement CSV line by line. A bad line becomes an error with its line number; the other lines still
 * count. Columns: date, description, debit, credit, balance (the header row must name them, in this order).
 */
final class StatementParser {

    static final List<String> HEADER = List.of("date", "description", "debit", "credit", "balance");
    static final int MAX_LINES = 10_000;
    static final int MAX_ERRORS_SHOWN = 100;

    /**
     * STRICT, so 31/02/2026 is an error instead of quietly becoming 28 Feb. STRICT needs "uuuu" (proleptic year),
     * not "yyyy" (year of era), or every date fails.
     */
    static final List<DateTimeFormatter> DATE_FORMATS = List.of(
            DateTimeFormatter.ofPattern("dd/MM/uuuu").withResolverStyle(ResolverStyle.STRICT),
            DateTimeFormatter.ofPattern("dd-MM-uuuu").withResolverStyle(ResolverStyle.STRICT),
            DateTimeFormatter.ISO_LOCAL_DATE);

    record Transaction(int line, LocalDate date, String description, long debitPaise, long creditPaise, long balancePaise) {
    }

    record LineError(int line, String field, String value, String message) {
    }

    record Result(String status, int linesRead, List<Transaction> transactions, int errorCount, List<LineError> errors) {
    }

    /** Thrown for a problem with the file as a whole (no header, too long): unchecked, the controller maps it. */
    static final class FileProblem extends RuntimeException {
        FileProblem(String message) {
            super(message);
        }
    }

    private StatementParser() {
    }

    static Result parse(String csv) {
        List<String> lines = csv.lines().toList();   // not strip(): a leading blank line must not shift the line numbers
        if (lines.isEmpty() || lines.getFirst().isBlank()) {
            throw new FileProblem("The file is empty.");
        }
        if (lines.size() - 1 > MAX_LINES) {
            throw new FileProblem("The file has " + (lines.size() - 1) + " lines; at most " + MAX_LINES + " can be read at once.");
        }
        checkHeader(lines.getFirst());
        List<Transaction> transactions = new ArrayList<>();
        List<LineError> errors = new ArrayList<>();
        for (int i = 1; i < lines.size(); i++) {
            int lineNumber = i + 1;   // as a spreadsheet shows it: the header is line 1
            if (lines.get(i).isBlank()) {
                continue;
            }
            try {
                transactions.add(parseLine(lineNumber, lines.get(i)));
            } catch (LineException e) {
                errors.add(new LineError(lineNumber, e.field, shorten(e.value), e.getMessage()));
            }
        }
        String status = errors.isEmpty() ? "COMPLETE" : transactions.isEmpty() ? "REJECTED" : "PARTIAL";
        return new Result(status, lines.size() - 1, transactions, errors.size(),
                errors.subList(0, Math.min(errors.size(), MAX_ERRORS_SHOWN)));
    }

    private static void checkHeader(String header) {
        List<String> names;
        try {
            names = CsvLine.split(header.replace("﻿", "")).stream().map(n -> n.toLowerCase(Locale.ROOT)).toList();
        } catch (LineException e) {
            throw new FileProblem("The header row cannot be read: " + e.getMessage() + ".");
        }
        if (!names.equals(HEADER)) {
            // the line itself is not echoed back: without a header it may well be the customer's first transaction
            throw new FileProblem("The first line must be the header " + String.join(",", HEADER) + ".");
        }
    }

    static Transaction parseLine(int lineNumber, String line) throws LineException {
        List<String> f = CsvLine.split(line);
        if (f.size() != HEADER.size()) {
            throw new LineException("line", line, "has " + f.size() + " fields; expected " + HEADER.size());
        }
        LocalDate date = date(f.get(0));
        String description = f.get(1);
        if (description.isEmpty()) {
            throw new LineException("description", "", "is empty");
        }
        long debit = paise("debit", f.get(2));
        long credit = paise("credit", f.get(3));
        if ((debit == 0) == (credit == 0)) {
            throw new LineException("debit", f.get(2) + " / " + f.get(3), "exactly one of debit and credit must have an amount");
        }
        return new Transaction(lineNumber, date, description, debit, credit, paise("balance", f.get(4)));
    }

    static LocalDate date(String text) throws LineException {
        for (DateTimeFormatter format : DATE_FORMATS) {
            try {
                return LocalDate.parse(text, format);
            } catch (DateTimeParseException tryTheNextFormat) {
                // unchecked, so nothing forced us to catch it: we do, to try the next format
            }
        }
        throw new LineException("date", text, "is not a real date in dd/MM/yyyy, dd-MM-yyyy or yyyy-MM-dd");
    }

    /** "1,23,456.50" (Indian grouping) or "123456.5" to paise. Empty is zero. No minus signs: debit and credit say it. */
    static long paise(String field, String text) throws LineException {
        if (text.isEmpty()) {
            return 0;
        }
        String plain = text.replace(",", "");
        if (!plain.matches("\\d{1,13}(\\.\\d{1,2})?")) {
            throw new LineException(field, text, "is not an amount like 1,234.50");
        }
        return new BigDecimal(plain).movePointRight(2).longValueExact();
    }

    private static String shorten(String value) {
        return value.length() <= 40 ? value : value.substring(0, 40) + "…";
    }
}

src/main/java/com/tijori/statementimport/CsvLine.java

Does
Splits one line into fields, honouring quotes.
Why
Twenty lines of plain Java instead of a dependency, for one simple format.
Without it
line.split(","), which breaks on "UPI/GROCER, BLR".
package com.tijori.statementimport;

import java.util.ArrayList;
import java.util.List;

/** Splits one CSV line (RFC 4180 style): commas separate fields, double quotes wrap fields that contain commas. */
final class CsvLine {

    private CsvLine() {
    }

    static List<String> split(String line) throws LineException {
        List<String> fields = new ArrayList<>();
        StringBuilder field = new StringBuilder();
        boolean quoted = false;
        for (int i = 0; i < line.length(); i++) {
            char c = line.charAt(i);
            if (quoted) {
                if (c == '"' && i + 1 < line.length() && line.charAt(i + 1) == '"') {
                    field.append('"');   // "" inside quotes is one quote
                    i++;
                } else if (c == '"') {
                    quoted = false;
                } else {
                    field.append(c);
                }
            } else if (c == '"') {
                quoted = true;
            } else if (c == ',') {
                fields.add(field.toString().strip());
                field.setLength(0);
            } else {
                field.append(c);
            }
        }
        if (quoted) {
            throw new LineException("line", line, "a quote is opened and never closed");
        }
        fields.add(field.toString().strip());
        return fields;
    }
}

src/main/java/com/tijori/statementimport/LineException.java

The checked exception: field, value and message for one line.

package com.tijori.statementimport;

/**
 * One line could not be read. Checked on purpose: every caller of parseLine must decide what a bad line means,
 * and the compiler will not let it forget. Carries the field and the value so the customer can find and fix it.
 */
class LineException extends Exception {

    final String field;
    final String value;

    LineException(String field, String value, String message) {
        super(message);
        this.field = field;
        this.value = value;
    }
}

package com.tijori.statementimport;

import java.math.BigDecimal;
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;
import java.time.format.ResolverStyle;
import java.util.ArrayList;
import java.util.List;
import java.util.Locale;
import java.util.Map;

/**
 * Reads the statement CSV line by line. A bad line becomes an error with its line number; the other lines still
 * count. Columns are found by name in the header row, in any order (challenge 2); each line's balance must follow
 * from the line before (challenge 1).
 */
final class StatementParser {

    static final List<String> HEADER = List.of("date", "description", "debit", "credit", "balance");

    /** Challenge 2: other names banks use for the same columns. */
    static final Map<String, List<String>> ALIASES = Map.of(
            "date", List.of("txn date", "transaction date", "value date"),
            "description", List.of("narration", "particulars"),
            "debit", List.of("withdrawal amt", "withdrawal"),
            "credit", List.of("deposit amt", "deposit"),
            "balance", List.of("closing balance"));

    /** Where each of the five columns is in this file. */
    record Columns(int date, int description, int debit, int credit, int balance, int count) {
    }
    static final int MAX_LINES = 10_000;
    static final int MAX_ERRORS_SHOWN = 100;

    /**
     * STRICT, so 31/02/2026 is an error instead of quietly becoming 28 Feb. STRICT needs "uuuu" (proleptic year),
     * not "yyyy" (year of era), or every date fails.
     */
    static final List<DateTimeFormatter> DATE_FORMATS = List.of(
            DateTimeFormatter.ofPattern("dd/MM/uuuu").withResolverStyle(ResolverStyle.STRICT),
            DateTimeFormatter.ofPattern("dd-MM-uuuu").withResolverStyle(ResolverStyle.STRICT),
            DateTimeFormatter.ISO_LOCAL_DATE);

    record Transaction(int line, LocalDate date, String description, long debitPaise, long creditPaise, long balancePaise) {
    }

    record LineError(int line, String field, String value, String message) {
    }

    record Result(String status, int linesRead, List<Transaction> transactions, int errorCount, List<LineError> errors) {
    }

    /** Thrown for a problem with the file as a whole (no header, too long): unchecked, the controller maps it. */
    static final class FileProblem extends RuntimeException {
        FileProblem(String message) {
            super(message);
        }
    }

    private StatementParser() {
    }

    static Result parse(String csv) {
        List<String> lines = csv.lines().toList();   // not strip(): a leading blank line must not shift the line numbers
        if (lines.isEmpty() || lines.getFirst().isBlank()) {
            throw new FileProblem("The file is empty.");
        }
        if (lines.size() - 1 > MAX_LINES) {
            throw new FileProblem("The file has " + (lines.size() - 1) + " lines; at most " + MAX_LINES + " can be read at once.");
        }
        Columns columns = columns(lines.getFirst());
        List<Transaction> transactions = new ArrayList<>();
        List<LineError> errors = new ArrayList<>();
        Long previousBalance = null;   // null after a line that could not be read: nothing reliable to compare with
        for (int i = 1; i < lines.size(); i++) {
            int lineNumber = i + 1;   // as a spreadsheet shows it: the header is line 1
            if (lines.get(i).isBlank()) {
                continue;
            }
            try {
                Transaction t = parseLine(lineNumber, lines.get(i), columns);
                Long expected = previousBalance;
                previousBalance = t.balancePaise();   // the next line follows the stated balance, so one slip is one error
                if (expected != null) {
                    long should = expected - t.debitPaise() + t.creditPaise();
                    if (should != t.balancePaise()) {
                        throw new LineException("balance", rupees(t.balancePaise()), "should be " + rupees(should)
                                + " (" + rupees(expected) + " - " + rupees(t.debitPaise()) + " + " + rupees(t.creditPaise()) + ")");
                    }
                }
                transactions.add(t);
            } catch (LineException e) {
                errors.add(new LineError(lineNumber, e.field, shorten(e.value), e.getMessage()));
                previousBalance = null;
            }
        }
        String status = errors.isEmpty() ? "COMPLETE" : transactions.isEmpty() ? "REJECTED" : "PARTIAL";
        return new Result(status, lines.size() - 1, transactions, errors.size(),
                errors.subList(0, Math.min(errors.size(), MAX_ERRORS_SHOWN)));
    }

    /** Challenge 2: each column's position, by its name or an alias, case-insensitive. Extra columns are ignored. */
    static Columns columns(String header) {
        List<String> names;
        try {
            names = CsvLine.split(header.replace("\uFEFF", "")).stream().map(n -> n.toLowerCase(Locale.ROOT)).toList();
        } catch (LineException e) {
            throw new FileProblem("The header row cannot be read: " + e.getMessage() + ".");
        }
        int[] at = new int[HEADER.size()];
        for (int c = 0; c < HEADER.size(); c++) {
            String column = HEADER.get(c);
            at[c] = names.indexOf(column);
            for (String alias : ALIASES.get(column)) {
                at[c] = at[c] >= 0 ? at[c] : names.indexOf(alias);
            }
            if (at[c] < 0) {
                throw new FileProblem("The header has no " + column + " column (also accepted: " + String.join(", ", ALIASES.get(column)) + ").");
            }
        }
        return new Columns(at[0], at[1], at[2], at[3], at[4], names.size());
    }

    static Transaction parseLine(int lineNumber, String line, Columns c) throws LineException {
        List<String> f = CsvLine.split(line);
        if (f.size() != c.count()) {
            throw new LineException("line", line, "has " + f.size() + " fields; expected " + c.count());
        }
        LocalDate date = date(f.get(c.date()));
        String description = f.get(c.description());
        if (description.isEmpty()) {
            throw new LineException("description", "", "is empty");
        }
        long debit = paise("debit", f.get(c.debit()));
        long credit = paise("credit", f.get(c.credit()));
        if ((debit == 0) == (credit == 0)) {
            throw new LineException("debit", f.get(c.debit()) + " / " + f.get(c.credit()), "exactly one of debit and credit must have an amount");
        }
        return new Transaction(lineNumber, date, description, debit, credit, paise("balance", f.get(c.balance())));
    }

    static LocalDate date(String text) throws LineException {
        for (DateTimeFormatter format : DATE_FORMATS) {
            try {
                return LocalDate.parse(text, format);
            } catch (DateTimeParseException tryTheNextFormat) {
                // unchecked, so nothing forced us to catch it: we do, to try the next format
            }
        }
        throw new LineException("date", text, "is not a real date in dd/MM/yyyy, dd-MM-yyyy or yyyy-MM-dd");
    }

    /** "1,23,456.50" (Indian grouping) or "123456.5" to paise. Empty is zero. No minus signs: debit and credit say it. */
    static long paise(String field, String text) throws LineException {
        if (text.isEmpty()) {
            return 0;
        }
        String plain = text.replace(",", "");
        if (!plain.matches("\\d{1,13}(\\.\\d{1,2})?")) {
            throw new LineException(field, text, "is not an amount like 1,234.50");
        }
        return new BigDecimal(plain).movePointRight(2).longValueExact();
    }

    private static String rupees(long paise) {
        return BigDecimal.valueOf(paise, 2).toPlainString();
    }

    private static String shorten(String value) {
        return value.length() <= 40 ? value : value.substring(0, 40) + "…";
    }
}

    record LineError(int line, String field, String value, String message) {
    }

    record Result(String status, int linesRead, List<Transaction> transactions, int errorCount, List<LineError> errors) {
    }

    /** Thrown for a problem with the file as a whole (no header, too long): unchecked, the controller maps it. */
    static final class FileProblem extends RuntimeException {
        FileProblem(String message) {
            super(message);
        }
    }

    private StatementParser() {
    }

    static Result parse(String csv) {
        List<String> lines = csv.lines().toList();   // not strip(): a leading blank line must not shift the line numbers
        if (lines.isEmpty() || lines.getFirst().isBlank()) {
            throw new FileProblem("The file is empty.");
        }
        if (lines.size() - 1 > MAX_LINES) {
            throw new FileProblem("The file has " + (lines.size() - 1) + " lines; at most " + MAX_LINES + " can be read at once.");
        }
        Columns columns = columns(lines.getFirst());
        List<Transaction> transactions = new ArrayList<>();
        List<LineError> errors = new ArrayList<>();
        Long previousBalance = null;   // null after a line that could not be read: nothing reliable to compare with
        for (int i = 1; i < lines.size(); i++) {
            int lineNumber = i + 1;   // as a spreadsheet shows it: the header is line 1
            if (lines.get(i).isBlank()) {
                continue;
            }
            try {
                Transaction t = parseLine(lineNumber, lines.get(i), columns);
                Long expected = previousBalance;
                previousBalance = t.balancePaise();   // the next line follows the stated balance, so one slip is one error
                if (expected != null) {
                    long should = expected - t.debitPaise() + t.creditPaise();
                    if (should != t.balancePaise()) {
                        throw new LineException("balance", rupees(t.balancePaise()), "should be " + rupees(should)
                                + " (" + rupees(expected) + " - " + rupees(t.debitPaise()) + " + " + rupees(t.creditPaise()) + ")");
                    }
                }
                transactions.add(t);
            } catch (LineException e) {
                errors.add(new LineError(lineNumber, e.field, shorten(e.value), e.getMessage()));
                previousBalance = null;
            }
        }
        String status = errors.isEmpty() ? "COMPLETE" : transactions.isEmpty() ? "REJECTED" : "PARTIAL";
        return new Result(status, lines.size() - 1, transactions, errors.size(),
                errors.subList(0, Math.min(errors.size(), MAX_ERRORS_SHOWN)));
    }

    /** Challenge 2: each column's position, by its name or an alias, case-insensitive. Extra columns are ignored. */
    static Columns columns(String header) {
        List<String> names;
        try {
            names = CsvLine.split(header.replace("\uFEFF", "")).stream().map(n -> n.toLowerCase(Locale.ROOT)).toList();
        } catch (LineException e) {
            throw new FileProblem("The header row cannot be read: " + e.getMessage() + ".");
        }
        int[] at = new int[HEADER.size()];
        for (int c = 0; c < HEADER.size(); c++) {
            String column = HEADER.get(c);
            at[c] = names.indexOf(column);
            for (String alias : ALIASES.get(column)) {
                at[c] = at[c] >= 0 ? at[c] : names.indexOf(alias);
            }
            if (at[c] < 0) {
                throw new FileProblem("The header has no " + column + " column (also accepted: " + String.join(", ", ALIASES.get(column)) + ").");
            }
        }
        return new Columns(at[0], at[1], at[2], at[3], at[4], names.size());
    }

    static Transaction parseLine(int lineNumber, String line, Columns c) throws LineException {
        List<String> f = CsvLine.split(line);
        if (f.size() != c.count()) {
            throw new LineException("line", line, "has " + f.size() + " fields; expected " + c.count());
        }
        LocalDate date = date(f.get(c.date()));
        String description = f.get(c.description());
        if (description.isEmpty()) {
            throw new LineException("description", "", "is empty");
        }
        long debit = paise("debit", f.get(c.debit()));
        long credit = paise("credit", f.get(c.credit()));
        if ((debit == 0) == (credit == 0)) {
            throw new LineException("debit", f.get(c.debit()) + " / " + f.get(c.credit()), "exactly one of debit and credit must have an amount");
        }
        return new Transaction(lineNumber, date, description, debit, credit, paise("balance", f.get(c.balance())));
    }

    static LocalDate date(String text) throws LineException {
        for (DateTimeFormatter format : DATE_FORMATS) {
            try {
                return LocalDate.parse(text, format);
            } catch (DateTimeParseException tryTheNextFormat) {
                // unchecked, so nothing forced us to catch it: we do, to try the next format
            }
        }
        throw new LineException("date", text, "is not a real date in dd/MM/yyyy, dd-MM-yyyy or yyyy-MM-dd");
    }

    /** "1,23,456.50" (Indian grouping) or "123456.5" to paise. Empty is zero. No minus signs: debit and credit say it. */
    static long paise(String field, String text) throws LineException {
        if (text.isEmpty()) {
            return 0;
        }
        String plain = text.replace(",", "");
        if (!plain.matches("\\d{1,13}(\\.\\d{1,2})?")) {
            throw new LineException(field, text, "is not an amount like 1,234.50");
        }
        return new BigDecimal(plain).movePointRight(2).longValueExact();
    }

    private static String rupees(long paise) {
        return BigDecimal.valueOf(paise, 2).toPlainString();
    }

    private static String shorten(String value) {
        return value.length() <= 40 ? value : value.substring(0, 40) + "…";
    }
}

Interview takeaways

Checked or unchecked: what is the difference?

A checked exception must be caught or declared, so the compiler makes callers think about it. An unchecked one (RuntimeException) can travel up unnoticed. Use checked for failures the caller is expected to handle, like a bad line.

Why is 31/02/2026 parsed as 28 February by default?

DateTimeFormatter.ofPattern uses ResolverStyle.SMART, which clamps an invalid day to the last day of the month. STRICT refuses it.

Why uuuu instead of yyyy with STRICT?

yyyy is year of era and needs an era field to resolve strictly; without one every date fails. uuuu is the proleptic year and needs nothing else.

How should a parser report errors?

With the line number, the field, the value and what was expected, for every bad line, so the user can fix them all in one go.

Why not split CSV on commas?

Fields may be quoted because they contain commas. A small state machine that tracks whether you are inside quotes handles it.
