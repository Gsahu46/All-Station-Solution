# Station 090 plan: Partner shipping-rate API docs

**Problem.** Dakroute (fictional courier): partners integrate from a PDF written by hand two releases ago; its field
names and units no longer exist, and 200 tickets a month follow.

**Endpoints.** `POST /rate-quotes` {fromPincode, toPincode, weightGrams, lengthCm, widthCm, heightCm, service}: 200
with zone, chargeable weight, price, GST and total in paise, estimated days; 400 for invalid input; 422 for a parcel
the network cannot carry (over 50 kg, PIN code not served). Demo tariff. `GET /v3/api-docs`: the OpenAPI 3.1
description, generated by springdoc-openapi 3.1.1 from the code.

**Docs from code.** Validation annotations give patterns and limits; @Schema adds descriptions and examples;
@Operation, @ApiResponse and named @ExampleObject document 200, 400 and 422 with examples; an OpenAPI bean adds the
title, version, contact and the partner server address (example).

**Trap.** `HandWrittenDocsTrapTest`: the PDF's example request gets 400; the generated schema has the real field names.

**Docs tested against the API.** `OpenApiDocsTest`: every request example is sent and must get the status of the
same-named response example (200 if none); every documented answer must match the real one; the fields the docs call
required are exactly those the API refuses when missing; the description equals the approved copy
(src/test/resources/openapi/approved.json), and a changed one is written to target/ for review.

**Found while building.** (1) springdoc marked only @NotNull fields required; Jackson 3 refuses a missing int too, so
the docs said weightGrams was optional while the API answered 400: requiredMode added, found by the required-fields
test. (2) The error examples first had "type": "about:blank", which Spring does not send: found by the
documented-answer test. (3) For a record, Jackson 3 reports a missing number before an unknown field (challenge 2).
(4) The GST rounding cannot happen with this tariff (all prices give whole paise): tested on the function.

**Mutations.** int field not required in docs -> 2; wrong documented total -> 2; field renamed -> 7; weight limit
changed -> 3; volumetric divisor -> 1; GST cut instead of rounded -> 1; no LOCAL zone -> 1; no slab rounding -> 3.

**Review.** Annotations removed ("springdoc generates it anyway") and too heavy answered 400: 4 of 11 fail.

**Practice.** 1: document the not-served 422 with examples. 2: name the wrong field in 400s. Both change the
description: the solution includes the approved copy (the build copies challenge/solution/test-resources/).
3 (paper): publishing docs and a changelog to partners.
